  完成的工作总结

  🔍 OCR系统优化 - 移除PaddleOCR,优化CnOCR配置

  我已经完成了OCR系统的优化,主要包括:

  1. 创建了OCR配置管理系统 (ocr_config.py)

  新建了统一的OCR配置文件,支持不同场景的模型选择:

  可用模型:
  - general - 通用模型 (densenet_lite_136-gru):
支持中文、英文、数字混合识别
  - number - 纯数字模型 (number-densenet_lite_136-gru):
  仅识别0-9数字,适用于伤害数字、血量等
  - document - 文档模型 (doc-densenet_lite_136-gru):
  适用于扫描文档、书籍等长文本

  任务配置映射:
  - map_name → general (地图名称识别)
  - quest_text → general (任务文本)
  - item_name → general (物品名称)
  - damage_number → number (伤害数字)
  - health_value → number (血量数值)
  - tier_input → number (等级输入)
  - document → document (文档长文本)

  2. 移除了PaddleOCR依赖

  - 从 map_name_recognizer.py 中完全移除了 PaddleOCR 相关代码
  - 只保留 CnOCR 作为唯一的 OCR 引擎
  - 移除了所有 PaddleOCR 的初始化、识别和错误处理代码

  3. 更新了MapNameRecognizer

  - 使用新的 OCR 配置系统自动选择合适的模型
  - 根据任务类型(map_name)自动加载对应的 OCR 模型配置
  - 简化了代码结构,提高了可维护性

  4. 当前OCR配置

  # 地图名称识别使用通用模型
  OCR Configuration:
  - Task: map_name
  - Detection Model: naive_det
  - Recognition Model: densenet_lite_136-gru (通用模型)
  - Description: General purpose model for mixed content
  - Use Case: Map names, quest text, general UI text

  ✅ 优势

  1. 统一配置管理: 所有OCR配置集中管理,易于维护和切换
  2. 场景优化: 针对不同识别场景选择最适合的模型
