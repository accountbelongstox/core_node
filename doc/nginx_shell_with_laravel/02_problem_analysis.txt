PROBLEM ANALYSIS: SHOW ALL WEBSITES NOT DISPLAYING
===================================================

Date: 2025-11-14
Issue: nginx_manager.sh "Show All Websites" not showing Laravel-added websites

1. PROBLEM DESCRIPTION
----------------------

User reports that when accessing:
dd.sh -> Service Manager -> Nginx (option 6) -> Show All Websites (option 6)

The websites added via Laravel artisan commands are not displayed.

-------------------------

2.2 Code Analysis
The list_sites function in nginx_manager.sh (lines 179-201):
```bash
list_sites() {
    show_header
    echo -e "${COLOR_BLUE}=== Nginx Sites Configuration ===${COLOR_RESET}"
    echo ""

    echo -e "${COLOR_CYAN}Sites Available:${COLOR_RESET}"
    if [ -d "$NGINX_SITES_AVAILABLE" ]; then
        ls -1 "$NGINX_SITES_AVAILABLE" 2>/dev/null || echo "  (none)"
    else
        echo "  Directory not found: $NGINX_SITES_AVAILABLE"
    fi
    echo ""

    echo -e "${COLOR_CYAN}Sites Enabled:${COLOR_RESET}"
    if [ -d "$NGINX_SITES_ENABLED" ]; then
        ls -1 "$NGINX_SITES_ENABLED" 2>/dev/null || echo "  (none)"
    else
        echo "  Directory not found: $NGINX_SITES_ENABLED"
    fi
    echo ""

    read -p "Press Enter to continue..."
}
```

Path variables (nginx_manager.sh lines 21-24):
```bash
WWW_ROOT=$(map_web_path "wwwroot")
NGINX_CONFIG_DIR=$(map_web_path "nginxconfig")
NGINX_SITES_AVAILABLE="$NGINX_CONFIG_DIR/sites-available"

```

2.3 Path Resolution Check
The script uses map_web_path from gvar_common.sh to resolve paths.

POTENTIAL ISSUE: If map_web_path returns incorrect paths, the directories won't be found.

Expected paths:
- NGINX_CONFIG_DIR: /www/nginxconfig
- NGINX_SITES_AVAILABLE: /www/nginxconfig/sites-available
- NGINX_SITES_ENABLED: /www/nginxconfig/sites-enabled

Actual verified paths (filesystem):
- /www/nginxconfig/sites-available/ EXISTS
- /www/nginxconfig/sites-enabled/ EXISTS

3. ROOT CAUSE ANALYSIS
----------------------

3.1 Hypothesis 1: Path Mapping Issue
If map_web_path() returns WSL-specific paths (e.g., /mnt/d/www/nginxconfig) while
files are in /www/nginxconfig, the list_sites function won't find the files.

Test needed: Verify what map_web_path("nginxconfig") returns in current environment.

3.2 Hypothesis 2: Permission Issue
The shell script might not have read permissions on nginx directories.

Test: Check if current user can read /www/nginxconfig/sites-available/

3.3 Hypothesis 3: Function Not Being Called
The menu option might not be calling the correct function.

Verified: nginx_manager.sh line 552 shows case 6 calls list_sites
```bash
case $choice in
    ...
    6) list_sites ;;
    ...
esac
```

3.4 Hypothesis 4: Display Issue
The ls command output might be lost or not displayed properly.

6. POTENTIAL SOLUTIONS
----------------------

Solution 1: Fix Path Mapping
If map_web_path returns incorrect path, update gvar_common.sh to return correct path
for nginxconfig in current environment.

Solution 2: Enhanced list_sites Function
Replace simple ls with more robust listing that:
- Shows domain name
- Shows type (from Laravel DB)
- Shows SSL status
- Shows enabled/disabled status
- Integrates with Laravel database for richer information

Proposed enhanced function:
```bash
list_sites() {
    show_header
    echo -e "${COLOR_BLUE}=== Nginx Sites Configuration ===${COLOR_RESET}"
    echo ""

    # Show file-based listing
    echo -e "${COLOR_CYAN}Sites Available (from filesystem):${COLOR_RESET}"
    if [ -d "$NGINX_SITES_AVAILABLE" ]; then
        ls -1 "$NGINX_SITES_AVAILABLE" 2>/dev/null || echo "  (none)"
    else
        echo "  Directory not found: $NGINX_SITES_AVAILABLE"
    fi
    echo ""

    # Show Laravel database listing
    echo -e "${COLOR_CYAN}Sites Managed by Laravel:${COLOR_RESET}"
    cd /www/programing/core_node/poly_apps/laravel_main
    php artisan servermanager:website list 2>/dev/null || echo "  Laravel database unavailable"
    echo ""

    read -p "Press Enter to continue..."
}
```

Solution 3: Unified Display
Create a new function that reads from Laravel database and displays
websites with full details, replacing the simple file listing.
