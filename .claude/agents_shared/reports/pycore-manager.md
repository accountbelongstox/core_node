## Findings

- FU-004 fixed. `components/PcTerminalDesktopIntegration.tsx` uses `useTranslation('pc')`; every `terminal.desktop.*` key and `common.refresh` exist in pc en/zh.
- FU-018 fixed. `pages/PcTerminalPage.tsx` maps `terminal_viewer_id_required`, `terminal_viewer_window_limit_exceeded`, `terminal_viewer_limit_exceeded` to new `terminal.errors.viewer*` keys (en/zh). The pycore RPC raises these as exceptions (HTTP error whose message is the code), so the windows refresh now keeps a known code from the error (`terminalRequestErrorCode`) instead of always `request_failed`; otherwise the new keys would never show. A diff of the pycore terminal codes against the map finds no other gap.
- FU-024 (pc part) fixed. `common.close` added to pc en/zh (used by `PcLayout.tsx:75` and `PcTerminalPage.tsx`). The lm parts belong to laravel-manager.
- FU-025 (pycore-manager parts) fixed.
  - `pages/vocabulary/vocabShared.tsx`: `VL` is now a map of `vocabularyPage.common.*` keys; `VocabLoading` translates.
  - Every Vocabulary tab moved its English label object (`L`, filter/sort option labels, table headers, `Stat` labels, T/A/V badges, placeholders, TTS/playback errors, the learning-panel worker table) to `vocabularyPage.{common,words,libraries,statistics,translate,learning}.*` (en/zh). The offline banner now says Laravel (these tabs call Laravel directly, not pycore). The statistics storage card labelled every section "Audio files"; it now says "Files".
  - `utils/pcFormat.ts`: `relativeTime`/`relativeAgo` take the `pc` `t` and use `common.relative.*` (one shared implementation); callers `PcVersionChips.tsx`, `PcRecentTasksPanel.tsx` updated.
  - Remainder (same rule, not named in the finding; deferred sweep): 10 pycore-manager files still keep an English `L` label object, 374 labels and about 450 use sites (`PcAddDocumentView`, `PcSentenceAudioPanel`, `PcBookSourceExplorer`, `PcVideoExtractContext`, `PcCoreBookPage`, `PcLaravelMediaPanel`, `PcImageSearchPage`, `PcVideoExtractPage`, `PcBooksPage`, `PcTranslatePage`). `pages/PcSubtitleSearchPage.tsx` (73 labels) is converted to `subtitlePage.*`. Also: `pages/vocabulary/VocabOfflineDictTab.tsx` passes `sourceLabel: 'pycore local'` to the shared ECDICT panel, whose own labels are English (shared layer). `components/PcPycoreTargetSwitcher.tsx` is converted under pycore-manager-5.
- FU-011 fixed. `VocabLibrariesTab.tsx` applies the language on blur/Enter (a draft state holds keystrokes), Refresh reloads, and a request sequence ref drops superseded responses before `setLibs` and `pcLibraryCoverTaskModel.track`. `VocabWordsTab.tsx` has the same per-keystroke loader; it got the same sequence guard (live search kept).
- FU-036 fixed. `PcAgentHistoryPage.tsx`: `sessionRequestSeq`, `promptRequestSeq`, `detailRequestSeq`; each loader checks after every await and before each `set*`, and only the latest request clears its loading flag.
- FU-037 fixed. `AudioOrchWorkspace.tsx` `loadTasks`: a call during an in-flight load sets `tasksReloadQueuedRef`; the running load loops once more, so one follow-up load always runs after a mid-flight request.
- FU-040 fixed. New `hooks/usePcSingleAudio.ts`: one audio element per view; a new clip stops the previous one; unmount stops playback. Used by `components/PcWordAudioPanel.tsx`, `pages/PcWordAudioPage.tsx` (its `playing` flag comes from the hook) and `pages/vocabulary/VocabTranslateTab.tsx` (same unmanaged `new Audio` pattern). `playWordClip` was not reused: it is wordnew-specific (notifies the wordnew queue center).
- FU-026 (pycore-manager parts) fixed. The local `humanBytes` copies in `PcWordAudioPage.tsx` and `PcSubtitleSearchPage.tsx` are gone (`utils/pcFormat.humanBytes`, which wraps `core/utils/formatBytes`). Their identical local `Badge` components were also replaced by `vocabShared.PresenceBadge`.
- FU-020 fixed. `LibraryCoverTaskModel.enqueue` keeps the results of chunks sent before a failure (restores only ids of unsent chunks), publishes, starts the poll, then rethrows. `poll` marks an active id inactive (phase from its cover status) when a successful status response (`items` is an array) omits it, so a deleted library no longer keeps the poll alive.
- FU-027 fixed (with laravel-manager's BaseAPI hunk). `shell/ShellLaravelEndpointBridge.tsx` no longer binds pycore's Laravel worker endpoint on mount or on every pycore health event; it binds what reaches it through `persistSharedBaseURL` and only retries a failed bind when pycore comes back. `ApiManager.switchEndpoint()` already calls `persistSharedBaseURL()` explicitly after a verified switch. laravel-manager (BaseAPI writer) removed the implicit `persistSharedBaseURL()` call from `BaseAPI.setSharedBaseURL()` in the working copy, so activation and the mixed-content failover no longer bind pycore.

- pycore-manager-5 (K6, K7, K7a, §5):
  - Route table (§5, K6): the shared transport already sends the shell's login token (`core/auth/AuthSession`) on every Laravel call, and the browser never signs. New `utils/pcErrorCodes.pcLaravelErrorMessage`: 401 opens the shared login window and shows `errorCodes.LARAVEL_LOGIN_REQUIRED`, 403 shows `errorCodes.LARAVEL_ADMIN_REQUIRED`, else the error text or `LARAVEL_REQUEST_FAILED`. Used by the vocabulary tabs (dictionary writes/batch, cover enqueue, validity report, TTS generate, reads), `hooks/TaskCenterState.ts` (task-center completed reads now i18n; its unused translation-queue methods with English literals were removed), and the `media/enrich` calls in `PcSentenceAudioPanel.tsx` (the batch error now reaches the error list instead of a fixed English text) and `PcBooksPage.tsx`. Polled queue-center reads (`PcQueueCenterExchange`) do not prompt login (they only mark the hub degraded).
  - K7a in `core/integrations/pycore/pycoreTarget.ts`: `isPycoreLoopbackHost` (from `LOCAL_RPC_LOOPBACK_HOSTS`, contract), `isPycoreDirectAccessAllowed` (loopback page only); stored, preset and recent direct targets are honored only when allowed; `setPycoreTarget` returns false for a refused direct target; presets carry `source` instead of English `hint`/label text; `isPycoreDashboardOrigin`/`pycoreDashboardOriginPorts` mirror pycore's contract origin allow-list (loopback × `nexus_dash_frontend`, `pycore_backend`).
  - `components/PcPycoreTargetSwitcher.tsx`: Current URL/Local are hidden on non-loopback pages, with the i18n relay hint (`pycoreTarget.relayOnly`/`rejected`); the whole component moved to `pycoreTarget.*` keys (en/zh); the obsolete PNA warning is gone.
  - K7 rejections (pycore `local_rpc_middleware`: 401 for non-loopback callers, 403 `local_rpc_host_forbidden`/`local_rpc_origin_forbidden`, body `{"error":{"code":X,"message":X}}`): `PycoreHttpError.code` carries the code (`core/integrations/pycore/PycoreClient.ts`); new `components/PcRpcAccessBanner.tsx` (mounted in `PcLayout.tsx`) shows `rpcAccess.remote` / `rpcAccess.codes.*` for a readable 401/403, the relay hint on a non-loopback page, and `rpcAccess.originHint` when pycore looks down and the page origin is not on the contract list. It is silent in relay mode (relay paths are unchanged). Note: pycore sends no CORS headers on rejections, so a cross-origin rejection is unreadable in the browser; the origin hint covers that case.
  - New pycore codes: `errorCodes.LARAVEL_ENDPOINT_UNKNOWN`, `system_settings_invalid` (shown by the settings save, whose three notices are now i18n), `open_file_type_forbidden` (shown by the video-extract open action).
  - Not done: `pnaBlockedReason`, `isPycoreSecureContext`, `pycoreLocalConnectionHint` in `pycoreTarget.ts` are no longer used (two carry English text); deleting them needs the `core/integrations/pycore/index.ts` export list (asked the orchestrator).

Reuse: duplicated `Badge`/`StatTile`/`nf` copies in these files now use `vocabShared.PresenceBadge` and `shared/books/BookStats` (`BookStatTile`, `formatBookMetric`).

- pycore-manager-7:
  - `core/integrations/pycore/index.ts` / `pycoreTarget.ts`: `pnaBlockedReason`, `isPycoreSecureContext`, `pycoreLocalConnectionHint` (and the `isSandbox` helper only they used) are deleted; grep found no caller outside the switcher, which no longer used them. Scoped to `requestLaravel` rather than every `readLaravelResponse` caller on purpose: the other callers (Qy account login, relay API, cloud clipboard) send no shared session (`includeAuth=false`), so their 401 means wrong credentials/device auth, not "log in to the dashboard". - pycore-manager-8: `components/PcRpcAccessBanner.tsx` now classifies through the shared `classifyPycoreAccess` (vortex-5, `core/integrations/pycore/pycoreAccess.ts`, contract `CLIENT_KEY_ERROR_CODES`/`LOCAL_RPC_ERROR_CODES`): the newest pycore debug record with 401/403 is classified from its code; otherwise, while pycore is not up, the page itself. pc wording per kind: `host_forbidden` → `rpcAccess.hostForbidden`, `origin_forbidden` → `rpcAccess.originForbidden`, `client_key_rejected`/`relay_only` → `pycoreTarget.relayOnly`, `origin_not_allowed` → `rpcAccess.originHint`, `unreachable` → no banner (pages keep their own offline text); silent in relay mode. The code-named locale keys `rpcAccess.codes.*` became kind-named keys, so no pycore error-code literal remains in pycore-manager.
