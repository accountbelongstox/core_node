This desktop dual-boots Windows 10 and Debian ("debian-gpu"). `D:` is shared, so `poly_apps/laravel_main/storage/frankenphp/{Caddyfile,routes}` and `D:\www\core_node\certs\local` are regenerated by whichever OS starts Laravel. Always back them up before regenerating.

- Only Windows PowerShell 5.1 is installed (no pwsh). Native args that contain inner double quotes (e.g. `php -r 'echo "x"'`) lose the quotes, so `start.ps1`'s `php -r` helpers fail there.
- `ncore-laravel-main` (NSSM) is retired; its body only disables itself. The real service is `ncore-laravel-frankenphp` (WinSW via Step175).
- The FrankenPHP Windows payload (`D:\www\frankenphp\bin`) loads no php.ini. Extensions need an ini in `D:\www\frankenphp\php-conf.d` with `extension_dir` set.
- A detached runtime that outlives Claude sessions: WMI `Win32_Process.Create`, which keeps the full user env and the elevated token. Pass `Win32_ProcessStartup` with `ShowWindow=0`: a visible console on the desktop got a Ctrl+C and killed the runtime.
- Adding a CA to any Windows trust store (certutil/mkcert -install) is denied to agents: a user decision. `mkcert -install` also opens a modal dialog. pycore uses certifi, so the Windows store would not help it anyway.
- `sys:init` prints invite codes as `• role: CODE_WITH_UNDERSCORES`. Filter that block out of any log you display.

**Why:** found during the D7 bring-up (2026-09-27); record in `.claude/agents_shared/d7/laravel_local.md`.
**How to apply:** check these before any local start or restart; see [[verify-in-process-without-writes]] and [[feedback-laravel-no-env]].
