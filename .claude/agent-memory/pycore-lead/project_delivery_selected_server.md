The Laravel delivery outbox (`pyutils/laravel/delivery_outbox.py`) and `endpoint_manager.py` were reworked so the server the user SELECTED (stored `current`) is the only delivery target.

- Failover (`resolve`, `resolve_for_ui`) only adopts routes whose namespace equals the selected server's; a foreign server that is up is never adopted (it is another database).
- `target_namespaces()` = `[selected]`; `reconcile()` skips non-selected namespaces unless `reason == manual`; `reconcile_reachable` became `reconcile_selected`.
- Drain/ready/has_pending/next_attempt_at are scoped by `deliverable_namespaces(kind)`: selected server only, or every server holding rows for a `DeliveryKind(pinned=True)` kind (audio lane rows); servers whose routes all failed are excluded and a single watcher (`_watch_servers`, 30 s) re-probes them. This ended the head-of-line blocking where 2,616 old rows of an offline server refilled the 25-row window every minute.
- `route_for_namespace` replaced `base_url_for_namespace`: fastest reachable route, re-probe only routes whose last probe is older than 30 s.
- `OUTCOME_SOURCE_GONE`: audio_cache.resource rows whose file vanished are dropped, not dead-lettered. Lane kinds still dead-letter (they need failure history).
- Failure while the server is offline gives the attempt back and counts no metric.

Upload rules (user instruction 2026-09-30, "uploads use progress detection, never timeouts, use the project libs"): `HttpProgressClient.request` sends uploads with read timeout None; stall = write idle (project progress detection via `HttpTransferProgress`/`http_transfer_contract`), peer liveness = TCP keepalive on the httpx transport (`network_constants.HTTP_KEEPALIVE_*`, `laravel_http_transport._keepalive_socket_options`). Only connect-level failures mark a server unreachable (`client.laravel_server_unreachable`); ReadTimeout/WriteTimeout and 504 do not. Never add a "response wait budget" constant.
Batch delivery (`_deliver_group`) claims rows first, then registers lease renewal only for claimed rows with `strict=False`; registering all rows first caused "ownership changed during upload" aborting whole batches. `audio_orch.output` retries ask the W7 diff (`_server_needs_output`) before re-sending the 3.5 MB ingest; Laravel `ingestTasks` is synchronous (wildcard validation of up to 5000 sentences + advisory lock), so a real fix is server-side async ingest (not done, Laravel role).

Cross-OS paths (the real cause of most "cached audio is missing" dead letters): the data dir is ONE NTFS tree shared by Windows and Linux (D:\www == /www/www, native Linux /www), but rows/ledger entries stored each OS's absolute path, so the other OS saw a missing file. `core_node_dirs.resolve_portable_path` re-roots a stored path onto this host; it is applied on read in `LaravelDeliveryRepository._row` (payload_path) and `AudioResourceRepository.page` (path). Ledger entries must never point at a retained outbox copy (`RETAINED_PAYLOAD_DIR_NAME`, deleted after delivery): `audio_resource_delivery.durable_clip_path` moves those bytes to `cache/audio_clips/<kind>/<sha[:2]>/<sha>.mp3` before recording.
Dead-letter cleanup DONE 2026-09-30 with the user's explicit go-ahead ("clear the rest, keep only the correct ones"): 18,825 dead letters -> 0; 5,416 clips rescued/refreshed into the ledger, 7,388 rows had no source file, 15,040 ledger entries with no file anywhere were dropped. sqlite backups in the session scratchpad `db_backup\`. The 19,196 pending rows (incl. the 2,616 parked `acef730b` articles) were kept. The running pycore had old code; reconcile (RPC delivery retry with `reconcile`) or a restart re-offers rescued clips to the server diff.
Laravel: `AppQyV1OrchAudioCtl::ingestTasks` validated `segments.*.timeline.*` with wildcard rules, which flatten the whole 3.5 MB body (tens of seconds). Now scalar fields use Laravel rules on a payload without the heavy arrays, `AppQyV1OrchIngestValidator` checks sentences/resources/segments/timelines linearly (6 MB / 100k entries = ~100 ms), tasks whose meta_hash is already stored skip deep validation, and task/segment reads select only hash/ready columns. Laravel is edited locally and auto-synced (~30 s); never boot it locally, `php -l` and standalone class probes only.
