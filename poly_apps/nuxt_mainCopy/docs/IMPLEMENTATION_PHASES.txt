NUXT MULTI-APP ARCHITECTURE IMPLEMENTATION PLAN
Based on Flutter Bloom Architecture Pattern
===============================================

PHASE 1: Directory Structure Setup
-----------------------------------
Goal: Create new directory structure without breaking existing code

Steps:
1. Run full_architecture_restructure.py in DRY-RUN mode
2. Review proposed changes
3. Execute restructure with backup
4. Verify all files moved correctly

Files to create:
- apps/app_main/router_app_main/index.ts
- apps/app_main/pages_app_main/index.vue
- apps/app_main/config_app_main/app-config.ts
- common/router/router-aggregator.ts (aggregates all app routes)

Expected result:
- New apps/ directory with app_{name} subdirectories
- New common/ directory with shared resources
- All existing files backed up
- Files moved to new locations

PHASE 2: Router System Refactor
--------------------------------
Goal: Implement per-app routing with main aggregator

Steps:
1. Create router_app_codemart/routes.ts
   - Define all CodeMart routes
   - Export route configuration

2. Create router_app_admin/routes.ts
   - Define all Admin routes
   - Export route configuration

3. Create router_app_example/routes.ts
   - Define all Example routes (components/, elements/, forms/, datatables/)
   - Export route configuration

4. Create router_app_dev/routes.ts
   - Define all Dev routes
   - Export route configuration

5. Create router_app_dashboard/routes.ts
   - Define all Dashboard routes
   - Export route configuration

6. Create router_app_main/index.ts
   - Import all app routes
   - Aggregate into single router for debugging
   - Export combined routes

7. Update nuxt.config.ts
   - Point to new router structure
   - Configure route resolution

Files to create/update:
- apps/app_codemart/router_app_codemart/routes.ts
- apps/app_admin/router_app_admin/routes.ts
- apps/app_example/router_app_example/routes.ts
- apps/app_dev/router_app_dev/routes.ts
- apps/app_dashboard/router_app_dashboard/routes.ts
- apps/app_main/router_app_main/index.ts
- nuxt.config.ts

Expected result:
- Each app owns its routes
- Main app aggregates all routes
- Routes can be individually enabled/disabled

PHASE 7: Localization (i18n) Setup
-----------------------------------
Goal: Implement per-app localization

Steps:
1. Create locale files per app:
   - apps/app_codemart/locales_app_codemart/en.json

   - apps/app_admin/locales_app_admin/en.json
   - apps/app_admin/locales_app_admin/zh.json
   (same for other apps)

2. Create common locales:
   - common/locales/en.json
   - common/locales/zh.json

3. Create locale aggregator in app_main:
   - apps/app_main/locales_app_main/aggregator.ts
   - Import all app locales
   - Merge with common locales

4. Update nuxt.config.ts i18n configuration
   - Point to new locale structure

Files to create:
- Per-app locale files
- Common locale files
- Locale aggregator
- Updated nuxt.config.ts

Expected result:
- Each app has own translations
- Common translations shared
- No translation key conflicts

NAMING CONVENTIONS
==================
All directories in apps/:
- app_{name}/                  # App root
- {resource}_app_{name}/       # App resource folder

Examples:
- apps/app_codemart/theme_app_codemart/
- apps/app_admin/stores_app_admin/
- apps/app_example/pages_app_example/

Benefits:
- Clear ownership
- No file name confusion
- Easy to search and filter
- Consistent across all apps
