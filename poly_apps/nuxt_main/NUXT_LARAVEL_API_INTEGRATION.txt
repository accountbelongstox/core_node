====================================================================================================
NUXT-LARAVEL API INTEGRATION GUIDE
====================================================================================================

This guide explains how Nuxt applications interact with Laravel backend API.

====================================================================================================
1. ARCHITECTURE OVERVIEW
====================================================================================================

Nuxt Frontend (Port 10001)  <-->  Laravel Backend API (Port 9003)
   - Vue 3 + Nuxt 4             - REST API endpoints
   - Client-side rendering      - Authentication
   - API consumption            - Business logic

====================================================================================================
2. API ENDPOINTS CONFIGURATION
====================================================================================================

Location: common/config/api-endpoints.ts

Global endpoints configured with priority system:
1. Remote: https://api.si.12gm.com (HTTPS, no port)
2. Remote: https://api.si.gm15.com (HTTPS, no port)
3. Local Domain: http://local.api.12gm.com (HTTP, port 80)
4. Local Domain: http://local.api.gm15.com (HTTP, port 80)
5. Local IP: http://192.168.2.1:9003 (HTTP, port 9003)
6. Local IP: http://192.168.50.2:9003 (HTTP, port 9003)

Features:
- Automatic health checking (every 60 seconds)
- Auto-failover to healthy endpoints
- HTTP 404 considered as "server reachable" (healthy)
- LocalStorage caching of health status
- Priority-based endpoint selection

====================================================================================================
3. GLOBAL API PLUGIN
====================================================================================================

Location: common/plugins/api-endpoints.client.ts

Initializes on app startup and provides:
- $apiEndpoints.getActiveBaseUrl(): Get current API URL
- $apiEndpoints.getActiveEndpoint(): Get endpoint object
- $apiEndpoints.checkAllEndpoints(): Trigger health check
- $apiEndpoints.selectBestEndpoint(): Select best endpoint
- Automatic initialization with cached/default endpoint
- Console logging for debugging

====================================================================================================
4. API HELPER FOR NON-COMPONENT CONTEXT
====================================================================================================

Location: common/utils/api-endpoints-helper.ts

Singleton class for accessing API endpoints outside Vue components:

import { apiEndpointsHelper } from '@/common/utils/api-endpoints-helper';

const baseUrl = apiEndpointsHelper.getActiveBaseUrl();
// Returns: "http://192.168.50.2:9003"

Usage in services:
- Authentication services (login, register)
- Data fetching services
- Any non-component TypeScript files

====================================================================================================
5. LARAVEL API ROUTES
====================================================================================================

Location: laravel_main/routes/api.php

All API routes are prefixed with /api:

Health Check:
  GET /api/health
  Response: {"status":"healthy","service":"Laravel API","timestamp":"...","version":"..."}

Authentication (IT Tools namespace):
  POST /api/login          - User login
  POST /api/register       - User registration
  GET  /api/user           - Get current user (requires token)
  POST /api/logout         - User logout
  POST /api/refresh        - Refresh access token

Headers Required:
  Content-Type: application/json
  X-App-Namespace: ittools (identifies which Nuxt app is calling)
  Authorization: Bearer {token} (for protected routes)

====================================================================================================
6. AUTHENTICATION FLOW
====================================================================================================

Step 1: User enters credentials in Nuxt login modal
  Location: app_ittools_pages/components/auth/LoginModal.vue

Step 2: Modal calls auth store
  Location: app_ittools_pages/stores/auth-store.ts
  Method: authStore.login(credentials)

Step 3: Store calls auth API service
  Location: app_ittools_pages/services/auth-api.ts
  Function: login(credentials)

Step 4: Service gets active API endpoint
  const baseUrl = apiEndpointsHelper.getActiveBaseUrl();
  // Returns: "http://192.168.50.2:9003"

Step 5: Make fetch request to Laravel
  fetch(`${baseUrl}/api/login`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-App-Namespace': 'ittools'
    },
    body: JSON.stringify({username, password})
  })

Step 6: Laravel processes request
  - Validates credentials
  - Returns: {user, token, refreshToken}

Step 7: Store saves to localStorage
  - ittools_auth_token
  - ittools_refresh_token
  - ittools_user

Step 8: User is authenticated, TopBar shows user info

====================================================================================================
7. CREATING NEW API INTEGRATIONS
====================================================================================================

Example: Add new "get user profile" endpoint

A. Laravel Side (laravel_main/routes/ItToolsV1Router/...)

   Route::middleware('auth:sanctum')->group(function () {
       Route::get('/profile', [ProfileController::class, 'show']);
   });

B. Nuxt Service Side (app_ittools_pages/services/profile-api.ts)

   import { apiEndpointsHelper } from '@/common/utils/api-endpoints-helper';

   export async function getUserProfile(userId: string) {
       const baseUrl = apiEndpointsHelper.getActiveBaseUrl();
       const token = localStorage.getItem('ittools_auth_token');

       const response = await fetch(`${baseUrl}/api/profile/${userId}`, {
           method: 'GET',
           headers: {
               'Authorization': `Bearer ${token}`,
               'X-App-Namespace': 'ittools'
           }
       });

       return response.json();
   }

C. Nuxt Component Side

   import { getUserProfile } from '@/app_ittools_pages/services/profile-api';

   const profile = await getUserProfile('123');

8. ERROR HANDLING
====================================================================================================

Common Errors:

"No active API endpoint available"
  - No endpoints configured or all unhealthy
  - Solution: Check API endpoint health in debug panel
  - Check localStorage for cached endpoint

"CORS Error"
  - Laravel CORS not configured for Nuxt origin
  - Solution: Update Laravel CORS config

"401 Unauthorized"
  - Missing or invalid token
  - Solution: Check token in localStorage, refresh if needed

"Network Error"
  - API server not running
  - Wrong port or URL
  - Solution: Verify Laravel is running on port 9003

====================================================================================================
10. BEST PRACTICES
====================================================================================================

1. Always use apiEndpointsHelper in services (not components)
2. Always use $apiEndpoints in components (via useNuxtApp())
3. Include X-App-Namespace header for all requests
4. Store tokens in localStorage with app-specific prefix
5. Handle token refresh on 401 errors
6. Validate API responses before using data
7. Show user-friendly error messages
8. Use TypeScript interfaces for API responses
9. Keep API base URL logic in one place (apiEndpointsHelper)
10. Test with different endpoints using debug panel

====================================================================================================
11. SECURITY CONSIDERATIONS
====================================================================================================

1. HTTPS for production endpoints
2. Token-based authentication (Bearer tokens)
3. HTTP-only cookies for refresh tokens (recommended)
4. CORS properly configured in Laravel
5. Rate limiting on Laravel API
6. Input validation on both client and server
7. Sanitize user input before sending to API
8. Never log sensitive data (tokens, passwords)
9. Use environment variables for sensitive config
10. Implement CSRF protection where needed
