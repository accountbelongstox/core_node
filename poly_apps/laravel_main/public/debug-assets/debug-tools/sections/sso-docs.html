SSO Authentication

Single Sign-On with WorkOS AuthKit · Laravel 13 + FrankenPHP/Octane

Overview Usage Deployment Embedding HTTP API Dashboard Login

Overview

The platform has two independent login surfaces:

  • Dashboard login (/auth/*) — username / email / phone + password against the canonical Laravel users table. Powers the login wall, the top-right user menu, registration and super-code elevation. Super administrators sign in with their real account.
  • SSO Authentication (/sso/*) — single sign-on through WorkOS AuthKit and organization identity providers (Google, Microsoft, GitHub, Apple). Related to the dashboard login (same user table, shared tokens) but dedicated to SSO federation.

Both issue Laravel Sanctum tokens through CommonAuthService::issueLoginToken(), so a token from either surface is valid across the platform.

Usage

  1. Open SSO Authentication in the sidebar (or navigate to /sso).
  2. Password tab: sign in with username / email / phone + password. When WorkOS credentials are configured this authenticates through WorkOS AuthKit; otherwise it falls back to Laravel-native authentication.
  3. SSO tab: optionally enter an Organization ID, pick a provider, then click Sign in with SSO. You are redirected to the identity provider and returned to /sso/callback.
  4. The generated SSO URL can be copied and shared: users who are already signed in get auto-authenticated; others see the login prompt first.

Deployment

1. WorkOS credentials (RuntimeConfigurationStore)

Persist these keys through RuntimeConfigurationStore; the start shell loads them before Laravel starts (they are read via config('services.workos.*')):

WORKOS_CLIENT_ID # AuthKit client ID WORKOS_API_KEY # WorkOS secret key (sk_...) WORKOS_CLIENT_SECRET # required for password authentication WORKOS_REDIRECT_URL # optional; defaults to {origin}/sso/callback

2. Dashboard authentication keys

DASHBOARD_LOCAL_DEBUG # 'true' (default): loopback requests bypass login # set to 'false' on shared hosts to force real login DASHBOARD_INVITATION_CODE # invitation code required for /auth/register; # unset closes self-registration DASHBOARD_SUPER_CODE # super code that elevates an account to # Super Administrator (rolelevel 100); unset closes elevation

3. FrankenPHP / Octane notes

  • The SSO plane runs under Laravel Octane; the server (FrankenPHP or Swoole) is selected by config/octane.php via WebServerPlane. No code changes are needed when switching servers: controllers are stateless per request and credentials come from the runtime store, never from static state.
  • Loopback detection relies on trustProxies (loopback proxy only) in bootstrap/app.php, so $request->ip() resolves the real client behind nginx + FrankenPHP and the debug bypass can never be spoofed by remote visitors.
  • HTTPS termination: with FrankenPHP the Octane HTTPS flag follows the same plane detection; WorkOS requires the redirect URL to match the registered callback exactly, including scheme.
  • Auth mutation endpoints are rate limited (throttle:dashboard-auth, 10/min per IP) following the Laravel 13 authentication guidelines.

Embedding Examples

Redirect login (server-rendered page)

<a href="/sso">Sign in with SSO</a> <!-- The page authenticates, then redirects to the identity provider and returns to /sso/callback?code=... which re-renders the SSO page with the session and bearer token injected. -->

Password login from any client (fetch)

// 1. Fetch a CSRF token (web routes are CSRF-protected) const { csrf_token } = await fetch('/csrf-token').then(r => r.json()); // 2. Sign in; the response carries a Sanctum bearer token const res = await fetch('/sso/authenticate', { method: 'POST', headers: { 'Content-Type': 'application/json', 'Accept': 'application/json', 'X-CSRF-TOKEN': csrf_token }, body: JSON.stringify({ email: 'user@example.com', password: 'secret' }) }); const { success, data } = await res.json(); localStorage.setItem('auth_token', data.token);

Authenticated API calls (Bearer token)

const res = await fetch('/auth/user', { headers: { 'Authorization': 'Bearer ' + localStorage.getItem('auth_token') } }); const { data } = await res.json(); console.log(data.user, data.is_super_admin);

Embedded iframe login inside a host app

<iframe src="https://api.example.com/sso" style="width:480px;height:820px;border:0"></iframe> <!-- The embedded page shares the host origin cookies when served from the same domain; for cross-origin hosts use the JSON API above and pass the token yourself. -->

curl

curl -s https://api.example.com/sso/user curl -s -X POST https://api.example.com/auth/login \ -H 'Content-Type: application/json' -H 'Accept: application/json' \ -d '{"identifier":"admin","password":"secret"}'

Dashboard Login & Privileges

  • Sign in: top-right Sign In button opens the embedded login modal (username / email / phone + password).
  • Register: embedded registration tab; requires the server invitation code when configured.
  • Elevate: Management page → Super Code Elevation → submit the server-configured super code to become Super Administrator (rolelevel 100).
  • Loopback bypass: same-machine requests resolve the highest-privilege account automatically (login-free local development). Disable with DASHBOARD_LOCAL_DEBUG=false.
  • Identity resolution order: Sanctum bearer token → web session → loopback debug bypass.
