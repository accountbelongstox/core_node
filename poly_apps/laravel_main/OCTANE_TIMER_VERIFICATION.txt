================================================================================
Octane Timer Service - Verification Guide
================================================================================

The Octane Timer automatically updates a test file every second to prove it's
running. This file is located at: /tmp/octane_timer_test.txt

================================================================================
STEP 1: Restart Octane Service
================================================================================

bash /www/programing/core_node/scripts/shells/linux/common/octane_service_manager.sh restart <domain> <port>

Example:
bash /www/programing/core_node/scripts/shells/linux/common/octane_service_manager.sh restart example.com 8000

Or use the default service:
systemctl restart octane-default-8000

================================================================================
STEP 2: Verify Timer is Running
================================================================================

Method 1: Watch the test file (updates every second)
-----------------------------------------------------
watch -n 1 cat /tmp/octane_timer_test.txt

You should see the timestamp updating every second:
    Octane Timer Test - Heartbeat
    ==============================
    Last Update: 2025-11-16 02:30:45
    Total Ticks: 123
    Status: Timer is running
    ==============================

Method 2: Check via Command Line
---------------------------------
cd /www/programing/core_node/poly_apps/laravel_main
php artisan octane:timer-status

This shows:
- Timer running status
- Total ticks
- Task statistics
- Test file status (should be FRESH if updated within 3 seconds)
- Pycore service discovery status

Method 3: Check via API (HTTP)
-------------------------------
# Get timer status
curl http://localhost/api/octane/timer/status

# Get task statistics
curl http://localhost/api/octane/timer/tasks

# Get test heartbeat file
curl http://localhost/api/octane/timer/test/heartbeat

The heartbeat endpoint returns:
{
    "success": true,
    "file_path": "/tmp/octane_timer_test.txt",
    "content": "Octane Timer Test - Heartbeat\n...",
    "last_modified": "2025-11-16 02:30:45",
    "seconds_ago": 1,
    "is_fresh": true
}

Method 4: Tail the test file
-----------------------------
tail -f /tmp/octane_timer_test.txt

The content should update every second.

================================================================================
STEP 3: Verify Pycore URL Discovery
================================================================================

Check if Pycore service is being discovered:
curl http://localhost/api/octane/timer/pycore/diagnostics

This shows:
- Current Pycore service URL
- Dynamic switching status
- Environment detection (WSL/Desktop)
- Service availability

Force refresh Pycore URL:
curl -X POST http://localhost/api/octane/timer/pycore/refresh

================================================================================
REGISTERED TASKS
================================================================================

1. test_timer_heartbeat (every 1 second)
   - Updates /tmp/octane_timer_test.txt with current timestamp
   - Proves timer is running

2. pycore_url_discovery (every 10 seconds)
   - Scans localhost and LAN for Pycore service (port 59000)
   - Automatically switches to available service
   - Caches result for 30 seconds

================================================================================
TROUBLESHOOTING
================================================================================

Problem: Test file not found
Solution: Octane might not be running or timer provider disabled
- Check if Octane is running: systemctl status octane-*
- Check logs: journalctl -u octane-* -f
- Verify FPM is not running instead

Problem: Test file is stale (not updating)
Solution: Timer tick might not be firing
- Restart Octane service
- Check Octane config: cat config/octane.php | grep server
- Verify Swoole is installed: php -m | grep swoole

Problem: Timer only runs on Octane-Swoole, not FPM
Solution: This is by design!
- The provider automatically detects server type
- Tasks are disabled on FPM to avoid issues
- Only Octane-Swoole supports tick events
