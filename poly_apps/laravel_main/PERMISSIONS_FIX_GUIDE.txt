================================================================================
Permissions Fix Guide - Using dd.sh
================================================================================

📋 OVERVIEW
===========

This guide explains how to fix permissions using the integrated dd.sh tool
instead of standalone scripts. The dd.sh tool provides a comprehensive menu
system for managing all aspects of the Core Node project.

================================================================================
🎯 QUICK FIX (1-Step Process)
================================================================================

Use dd.sh Permissions Repair Menu
----------------------------------
Run dd.sh from the Core Node root directory:

    sudo dd.sh

Navigate the menu:
1. Select: "Linux Management"
2. Select: "Permissions Repair Menu"
3. Choose repair option based on your needs:

   Option 1: Essential Repair (Fast)
   - Core Node root & scripts only
   - Recommended for script execution issues

   Option 2: Full Core Node Repair ⭐ RECOMMENDED
   - All project directories (scripts, pycore, ncore, apps, pyapps)
   - Laravel database directory (/www/wwwroot/laravel_db/)
   - Comprehensive fix for ALL permission issues
   - ✅ Includes Laravel database permissions

   Option 3: Python Permissions
   - pycore & pyapps directories only
   - For Python-related permission issues

   Option 4: Node.js Permissions
   - ncore & apps directories only
   - For Node.js-related permission issues

   Option 5: /var/_core_node Permissions
   - MyBest directories
   - For system-wide installations

   Option 6: Environment Variables Setup
   - Sets up environment variables
   - Configures system paths

   Option 7: AI Tools Repair
   - claude, codex, droid tools
   - For AI development tools

   Option 8: Complete System Repair
   - Runs all of the above
   - Nuclear option for serious issues

⚠️ IMPORTANT: You must run dd.sh with sudo for permissions repair:
    sudo dd.sh

================================================================================
🔧 WHAT DOES EACH OPTION FIX?
================================================================================

Option 1: Essential Repair (Fast)
----------------------------------
Fixes:
✓ Core Node root directory permissions
✓ Scripts directory permissions
✓ Makes all .sh files executable

Time: ~5 seconds
Scope: Minimal
Use when: Quick script execution fix needed

Option 2: Full Core Node Repair (Recommended)
----------------------------------------------
Fixes:
✓ Core Node root directory (chmod 777)
✓ Scripts directory (chmod 777)
✓ Python directories: pycore, pyapps (chmod 777)
✓ Node.js directories: ncore, apps (chmod 777)
✓ Laravel database directory: /www/wwwroot/laravel_db/ (www-data:www-data, chmod 775)
✓ SQLite database files (chmod 664)
✓ JSON status files (chmod 664)
✓ All .sh files made executable (chmod 755)
✓ Ownership set to real user

Time: ~30 seconds
Scope: Comprehensive (includes Laravel)
Use when: Any permission issues

Option 3: Python Permissions
-----------------------------
Fixes:
✓ pycore directory (chmod 755)
✓ pyapps directory (chmod 755)
✓ .py files (chmod 644)
✓ __pycache__ directories (chmod 755)
✓ Ownership set to real user

Time: ~10 seconds
Scope: Python-specific
Use when: Python import/execution errors

Option 4: Node.js Permissions
------------------------------
Fixes:
✓ ncore directory (chmod 755)
✓ apps directory (chmod 755)
✓ .js files (chmod 644)
✓ node_modules directories (chmod 755)
✓ Ownership set to real user

Time: ~10 seconds
Scope: Node.js-specific
Use when: npm/node execution errors

Option 5: /var/_core_node Permissions
--------------------------------------
Fixes:
✓ /var/_core_node directory and subdirectories
✓ System-wide installation paths

Time: ~15 seconds
Scope: System-wide
Use when: System installation issues

Option 6: Environment Variables Setup
--------------------------------------
Sets up:
✓ System environment variables
✓ PATH configurations
✓ Shell profiles

Time: ~5 seconds
Scope: Environment
Use when: Command not found errors

Option 7: AI Tools Repair
--------------------------
Fixes:
✓ Claude tool permissions
✓ Codex tool permissions
✓ Droid tool permissions

Time: ~10 seconds
Scope: AI development tools
Use when: AI tool execution issues

Option 8: Complete System Repair (Nuclear Option)
--------------------------------------------------
Runs ALL of the above in sequence:
1. Full Core Node Repair
2. /var/_core_node Permissions
3. Environment Variables Setup
4. AI Tools Repair

Time: ~60 seconds
Scope: Everything
Use when: Multiple issues or unknown cause

🎯 COMMON SCENARIOS
================================================================================

Scenario 1: "bash: ./dd.sh: Permission denied"
-----------------------------------------------
Solution:
1. chmod +x dd.sh
2. Run: dd.sh
3. Select: Linux Management > Permissions Repair Menu
4. Select: Option 1 (Essential Repair)

Scenario 2: "npm install" fails with EACCES
--------------------------------------------
Solution:
1. Run: dd.sh
2. Navigate to: Permissions Repair Menu
3. Select: Option 4 (Node.js Permissions)

Scenario 3: Python import errors
---------------------------------
Solution:
1. Run: dd.sh
2. Navigate to: Permissions Repair Menu
3. Select: Option 3 (Python Permissions)

Scenario 4: Laravel "Permission denied" errors
-----------------------------------------------
Solution:
1. Run: sudo dd.sh
2. Navigate to: Permissions Repair Menu
3. Select: Option 2 (Full Core Node Repair)
4. Done! Laravel database permissions are automatically fixed

Scenario 5: Multiple unknown issues
------------------------------------
Solution:
1. Run: sudo dd.sh
2. Navigate to: Permissions Repair Menu
3. Select: Option 8 (Complete System Repair)
4. Done! All permissions are automatically fixed

================================================================================
🔍 VERIFICATION
================================================================================

After Running Permissions Repair:
----------------------------------

1. Verify dd.sh is executable:
   ls -la dd.sh
   # Should show: -rwxr-xr-x

2. Verify scripts directory:
   ls -la scripts/
   # Should show: drwxrwxrwx

3. Verify Laravel database (manual check):
   ls -la /www/wwwroot/laravel_db/
   # Should show owner: www-data:www-data
   # Directories: drwxrwxr-x (775)
   # SQLite files: -rw-rw-r-- (664)

4. Test Laravel initialization:
   php artisan sys:init
   # Should complete without permission errors
