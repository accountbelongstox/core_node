MCPCTL REFACTORING SUMMARY - Route Organization Cleanup
Date: 2025-11-23
================================================================================

OBJECTIVE:
Move all MCP route organization from pycore/pyctl/mcpctl to pycore/callmodule,
keeping only business logic handlers in mcpctl.

================================================================================

================================================================================

   - meta.py - Cleared (route registration moved)
   - file.py - Cleared (route registration moved)
   - database.py - Cleared (route registration moved)
   - codebase.py - Cleared (route registration moved)
   - __init__.py - Marked as deprecated module

2. DEPRECATED RPC Route Registration:
   - backend/rpc_routes.py - Marked as deprecated
     * register_mcp_routes() now shows deprecation warning
     * Points users to pycore/callmodule/routers/mcp_router.py

3. ACTIVE Route Organization (pycore/callmodule/routers/):
   - mcp_router.py - All 22 MCP routes registered here
     * Uses FastAPI APIRouter with /mcp prefix
     * References handlers from pycore.pyctl.mcpctl.backend.handlers
     * Auto-initializes controllers on first request

METHOD SIGNATURE ALIGNMENT:
================================================================================

All handler methods follow the same signature pattern:

    async def handle_xxx_async(
        params: Dict[str, Any],
        request_id: str = None,
        context: Dict = None
    ) -> Dict[str, Any]:

All router calls follow the same pattern:

    result = await handlers.handle_xxx_async(params, None, None)

VERIFIED: All 22 MCP tool handlers are properly aligned.

MIGRATION GUIDE:
================================================================================

OLD WAY (Standalone MCP Backend):
    python -m pycore.pyctl.mcpctl.mcp_backend_main

NEW WAY (Unified Backend):
    python pycore_module_caller.py

All MCP tools now available at:
    POST http://localhost:59000/mcp/<tool_name>

Examples:
    POST http://localhost:59000/mcp/backend_info
    POST http://localhost:59000/mcp/get_file_info
    POST http://localhost:59000/mcp/database_execute_query
    POST http://localhost:59000/mcp/codebase_search_content

================================================================================
BENEFITS OF REFACTORING:
================================================================================

1. Single Unified Backend:
   - One process (pycore_module_caller) serves all APIs
   - No need for separate MCP backend process
   - Reduced resource usage and complexity

2. Centralized Route Management:
   - All routes in pycore/callmodule/routers/
   - Consistent pattern across all routers
   - Easier to maintain and extend

3. Separation of Concerns:
   - mcpctl focuses on business logic (handlers + controllers)
   - callmodule focuses on API routing (FastAPI routers)
   - Clear responsibility boundaries

4. Better Integration:
   - MCP tools integrated with other pycore services
   - Shared middleware (CORS, logging, etc.)
   - Unified documentation (FastAPI /docs)
