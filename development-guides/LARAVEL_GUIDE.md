# Laravel Aggregated Application — Core Development Guide

Core rules for `laravel_main`. Follow the existing code style; English only; reuse before adding.

## 1. Framework & boot
- **Runtime upgrade override:** `laravel_main` runs as a FrankenPHP worker with HTTPS/HTTP/3 and 103 Early Hints; `wordnew`, the shared Pycore UI, `pycore-manager`, and `laravel-manager` must consume this capability through centralized contracts and transports.
- **Tailnet:** when the mesh VPN is connected, 175 (`--domains-only`; Windows Step175) idempotently adds, on top of the public domains, `https://<machine>.<tailnet domain>` → UI 13054, `/laravel-api` → 9000 and `/pycore-api` → 59000 (`X-Forwarded-Prefix`; paths in `service_contract.json#access.tailnet`). The tailnet domain is the active provider's (`access.mesh`: Headscale `mesh.<region>.<root>` by default, Tailscale `<tailnet>.ts.net`); `ServiceContract::tailnetDomainOf` matches either.
- **pycore boundary:** Laravel never calls pycore. Only pycore sends requests to Laravel. Laravel uses AI only through remote APIs and keys. It never runs local models, TTS/STT commands, GPU work or CPU-heavy tools; it marks such work as available tasks for pycore to pull and complete.
- **AI gateway:** when a configured key provides an AI capability (chat, translation, vision, image), Laravel calls that remote API itself through one gateway. Only work that no available key can serve becomes a pycore task.
- **Light local work:** Laravel keeps low-frequency or light PHP work itself (GD thumbnails, ItTools utilities). Each job is capped at 5% CPU and 5% memory and runs on both Linux and Windows; an endpoint that cannot be ported is marked `linux-only` in its API info.
- Laravel 13 on PHP 8.4+, pure headless API on port **9000**. `routes/web.php` is the immutable debug entry (`/`, `/api_info`) — never modify it, `app/Console`, or `app/Events`.
- Follow the Laravel 13 upgrade contract: use `PreventRequestForgery`, keep cache unserialization disabled unless classes are explicitly allow-listed, provide non-empty `uniqueBy` values to `upsert`, and never instantiate a model from its own boot cycle.
- **Live API & deploy sync:** the live API is https://api.si.12gm.com/; its code lives ONLY in local `poly_apps/laravel_main` — modify locally, never test locally. Code reaches the server through `gitsync` (commit, pull and push to the shared repository); the server pulls it, then deploys with `php artisan sys:init` and an Octane restart.
- **Server code sync without SSH (AI ops):** `dd.cmd gitsync -m "<desc>" --notice-laravel` (Linux `dd.sh ...`) pushes, then calls `POST /api/system/code-sync` (client key, client `shell`; single-flight job: server `gitsync --skip-notice-laravel`, `migration:check-safety` + `migrate --force`, FrankenPHP worker restart) and polls `GET /api/system/code-sync/status[?job_id=]` (phase, commit before/after, output tails, error). Contract: `config/service_contract.json` `code_sync`. Signed calls from any shell: `node ncore/foundation/common/laravel_signed_cli.js request <METHOD> <path> [--json <body>]` / `... code-sync`. **Scheduled self-sync:** the Laravel scheduler (`routes/console.php`, every `code_sync.schedule_minutes`) starts the same single-flight job as kind `scheduled` (fetch; no-op `result: up_to_date` when clean and level with `origin/main`, otherwise gitsync + migrate + reload); `GET /api/system/code-sync/history[?limit=]` returns server `head`/`origin_main` (commit, date, subject), `ahead`/`behind`, recent `commits` and the latest `jobs` (kind, phase, commit before/after, output tails, error); CLI: `... laravel_signed_cli.js history [--limit n]`.
- **App downloads mirror (AI ops):** a build publishes its APK to the local `<data dir>/downloads/<app>/` tree, then `POST /api/system/app-downloads/sync` (client key; body `{app, source_base_urls[]}`) queues a single-flight systemd job that fetches `<base>/downloads/<app>/manifest.json` from the first reachable source, downloads changed files (sha256 verified, resumable), renames them into the server tree and prunes to `keep_versions`; `GET /api/system/app-downloads/status[?job_id=]` reports it. It refuses when free disk minus the download would drop below `app_downloads.server_sync.min_free_bytes_after`. Fallback when no source is reachable: chunked `POST .../upload` (JSON `{app,file,size,sha256,offset,chunk_b64,chunk_sha256}`, resumable via the returned offset) then `POST .../upload/commit {app, manifest}`. FrankenPHP serves `/downloads/` and the contract `public_alias` (e.g. `/wordnew.apk`) from that tree. Contract: `config/service_contract.json` `app_downloads`.
- **Reading the live Laravel log (AI ops):** `GET /api/internal/pycore/logs/latest` (client key) with `file_id` (e.g. `laravel-2026-10-02`), `offset` cursor (omit = newest `max_bytes`, ≤1 MB, backwards), `limit` (≤500), `level` (e.g. `error`), `contains` (case-insensitive); entries: timestamp, level, channel, message, context; `next_cursor` continues forward. Example: `node ncore/foundation/common/laravel_signed_cli.js request GET "/api/internal/pycore/logs/latest?level=error&limit=50&max_bytes=1048576"`. Octane reloads only after the code-sync job finishes: wait for its status before trusting the newest log lines.
- **All of Laravel's pre-logic is owned by SHELL scripts and runs under root**: `dd.sh`/`dd.cmd` (installer) → `scripts/shells/.../install_shells` provision PHP/FrankenPHP/Node/PostgreSQL → step 175 boots the FrankenPHP Octane worker as systemd unit `ncore-laravel-frankenphp`; `pyservice.sh` runs pycore. Migrations/init happen ONLY via `php artisan sys:init` — never `Artisan::call('migrate')`.

## 2. System paths & filesystem (MANDATORY)
- Every system directory goes through `App\Providers\PathMapper` (merged DatabasePathHelper/ExternalStorageHelper/WebPathHelper) and `App\Utils\FileSystemManager`. **Search the code for an existing getter first**; never native `file_*`/`mkdir`/`scandir` or hardcoded paths.
- PathMapper is the PHP path constant center (`WINDOWS_DATA_DRIVE_ROOT`, `CORE_NODE_DATA_DIR_NAME`, `CACHE_DIR_NAME`, `GLOBAL_VAR_DIR_NAME`, …); keep it in sync with `pycore/pyfoundations/core_node_dirs.py`, `ncore/foundation/common/system_paths.js`, `scripts/shells/linux/common/runtime_environment.sh` and `scripts/shells/win/win_common/SharedCacheEnv.ps1`. Add new dirs there, never as literals elsewhere.
- Canonical roots (`CORE_NODE_DATA_DIR` / `CORE_NODE_CACHE_DIR` env win): data `getCoreNodeRuntimeDir()` → `D:\www\core_node` | `/www/www/core_node` (NTFS dual-boot) | `/www/core_node`; cache `getSharedDownloadCacheDir()` → `D:\www\cache` | `/www/www/cache` | `/var/_core_node/cache`; var center `<data>/global_var/<OS_TAG>_<KEY>` (shared keys bare), legacy `/var/_core_node/global_var`, `D:\programing\Users\<user>\.core_node\.global_vars` and `~/.core_node` are read-only fallbacks. Shell/PHP/Python/JS resolve the **same** paths.
- Cross-OS (scan code for the exact branch): WSL → `/mnt/d`; Linux (Ubuntu/Debian/Kali) → persisted `WWW_PATH`, else `/www/www` when `/www` is a mounted NTFS dual-boot root (`D:\www` == `/www/www`), else `/www`; Windows → `D:\www`; the source tree may stay on NTFS via `getCoreNodeDir()`. PostgreSQL data is pinned to native `/var/lib/postgresql/d`.
- FileSystemManager wraps all fs ops, auto-chowns to the real desktop user via `SystemUserDetector` (root service), and symlinks external paths into `storage/external/`.

## 3. Database — PostgreSQL only
- PostgreSQL is the **only** active engine (Linux+Windows); driver/host/port/user are fixed in `config/database.php`, password comes from the shell secret store — never read DB config from `.env`. MySQL/SQLite entries are inert stubs.
- One database per sub-app on `localhost:5432` (shared `core_node_main` + `app_qy_v1`, …). Resolve via `AppTablePrefixServiceProvider::getConnection()/buildTableName()` + `App\Constants\AppKeys`; never hardcode connection/table strings (use `{app}TablesMaps` / `GlobalTablesMap`).
- Idempotent never-rebuild migrations: `SafeMigrationHelper::alignTableStructureFromArray()` (create-if-missing + add columns; never drop/truncate in `up()`), enforced by `CheckMigrationSafety`, executed only by `sys:init`. `global_*` files use the default connection; `{appNameWithVersion}_*` files set their own app connection.
- Idempotent extensions may only add/modify table structure & data — never drop or delete columns or data.

## 4. Multi sub-app model framework
- Each app lives in `app/Apps/{appNameWithVersion}/` (version-pinned `{Vx}`); **every filename carries `{appNameWithVersion}`**. Controllers use the **`Ctl`** suffix under `{app}Controllers/`; per-app `{app}Models`/`{app}Services`/`{app}Utils`/`{app}Gvar`. Shared code only in `app/Utils`, `app/Providers`, `app/Helpers` (don't grow Helpers).
- Routes per app in `routes/{appNameWithVersion}Router/`, aggregated by `routes/api.php`. Each app exposes `{app}ApiInfo.php`; all metadata is surfaced at `/api_info`.
- Controllers MUST use `App\Traits\ApiResponse` + `App\Helpers\AuthHelper`; no try-catch; error messages must state the exact cause.

## 5. Data-processing model — Octane + pycore + chrome-mcp
- Octane (FrankenPHP worker, :9000) is the **sole** task driver: `OctaneTimerServiceProvider` ticks 1s and runs `TimerTasks/*`; no `queue:listen`/scheduler.
- Laravel is the single scheduler; **pycore** nodes and **chrome-mcp** (`apps/mcp-chrome`) are pull workers that only call Laravel. Word/sentence audio and translation gaps are handed out as disjoint work leases (contract `work_leases`) by compute class (gpu|cpu) and engine × language capability; other pycore work goes through `global_tasks` claimed atomically by `execution_type` lane + capability. Laravel never calls pycore (no PHP→pycore bridge exists).

## 6. UI end
- The UI is `poly_apps/pycore_laravel_wordnew_ui` (React/Vite shell wrapping laravel-manager); it calls Laravel `:9000` with stored-first multi-endpoint health-check failover. The frontend goes through TypeScript data models — components never call APIs directly.
- Build/run any `poly_apps/*` frontend only via its `scripts/start.sh` (pnpm + Vite; `-f` recreates `node_modules`). The installed pnpm is **v11**: each native/postinstall dep must be approved as `allowBuilds: { dep: true }` in that project's `pnpm-workspace.yaml`, else `pnpm install` aborts with `ERR_PNPM_IGNORED_BUILDS`. `onlyBuiltDependencies` and the `package.json` `packageManager` pin are dead (corepack off — global v11 runs).
