# file_sync 项目功能分析（归档）

归档日期：2026-04-04
语言：简体中文（zh-CN）

## 1. 项目定位

`file_sync` 是一个基于 Python 的 TCP 文件同步工具，用于将客户端目录持续镜像到服务端目录，支持“首次全量同步 + 后续增量同步”。

## 2. 核心角色与职责

- 客户端（`client.py`）
  - 扫描本地目录并维护快照（`mtime` + `size`）。
  - 通过交互输入与服务端显示的两位配对码认证（不再使用配置文件中的固定配对串）。
  - 执行清点式同步（manifest）或监听后增量推送（push）。
  - 支持 `watchdog` 监听与轮询降级。

- 服务端（`server.py`）
  - 提供 TCP 监听与并发连接处理。
  - 校验认证、接收 manifest/push、写入文件与删除孤儿文件。
  - 对文本文件做换行归一（CRLF -> LF）。

- 协议层（`protocol.py`）
  - 提供统一帧协议：4 字节长度前缀 + JSON 帧。
  - 提供文件 payload 接收与路径安全工具。

## 3. 同步流程

### 3.1 首次/清点式同步（manifest）

1. 客户端连接服务端并发送 `auth`。
2. 服务端校验配对码并返回 `auth_ok`。
3. 客户端发送 `manifest`（每个文件的 `mtime`、`size`）。
4. 服务端对比本地文件并返回 `sync_plan.upload`（需上传文件列表）。
5. 客户端按计划上传文件，最后发送 `bye`。
6. 服务端返回 `sync_done` 汇总结果。

该模式下服务端会删除“服务器存在但客户端不存在”的文件，保证目录镜像一致。

### 3.2 增量推送（push）

1. 客户端监听到变更后，发送 `push`，携带删除列表。
2. 服务端先执行删除，再接收变更文件。
3. 客户端发送 `bye`，服务端回 `sync_done`。

该模式不做 manifest 比较，强调低时延更新。

## 4. 关键能力

- 大量默认排除规则，减少无关文件同步（如 `.git`、`node_modules`、`__pycache__`、构建产物等）。
- 支持用户在 `client_config.json` 追加 `exclude`。
- 首次全量同步完成后写入 `.sync_client_state.json`，避免每次重启都跑“首次流程”。
- 监听模式使用防抖聚合事件，减少频繁推送。
- 文件写入采用临时文件 `.part` + 原子替换，降低半写入风险。

## 5. 协议与安全边界

- 路径安全：`safe_rel` 禁止 `..` 路径穿越；服务端 `_under_root` 再次确保写入不越界。
- 传输限制：JSON 帧与文件 payload 设有大小上限，避免异常大包。
- 认证方式：服务端随机两位码 + 客户端交互输入（轻量鉴权）。

## 7. 已知风险与注意事项

- 当前为明文 TCP + 共享码认证，公网环境建议加密隧道或 TLS。
- 差异判断依赖 `mtime + size`，未做内容哈希校验。
- 增量 push 为无逐文件 ACK 设计，吞吐较高但问题定位依赖日志。

## 8. 结论

该项目已具备实用的“目录镜像同步”能力，结构清晰，路径安全与异常处理基本完备，适合内网或受控环境下的持续同步场景。
