# 百度网盘媒体文件压缩工具

自动扫描、压缩百度网盘下载目录中的图片、视频和音频文件，支持断点续传和安全替换。

## 功能特点

### ✨ 核心功能
1. **自动扫描** - 递归扫描指定目录，识别所有图片、视频、音频文件
2. **智能去重** - 基于文件名自动识别重复的视频/音频文件
3. **分阶段处理** - 复制→压缩→验证→替换，确保原始文件安全
4. **断点续传** - 支持中断后继续处理，不会重复已完成的任务
5. **质量可控** - 可配置压缩参数（分辨率、质量、比特率等）

### 📦 压缩策略

#### 图片压缩
- 最大分辨率：720P（保持等比例）
- 文件大小阈值：500KB
- JPEG质量：85%
- 自动转换RGBA到RGB
- 使用PIL/Pillow库

#### 视频压缩
- 使用ffmpeg + H.264编码
- CRF质量控制：28（推荐18-28）
- 最大分辨率：720P
- 音频：AAC 128kbps
- 优化流媒体播放

#### 音频压缩
- 使用ffmpeg + AAC编码
- 比特率：128kbps
- 移除视频流（如果存在）

## 安装依赖

### 1. Python库
```bash
pip install Pillow
```

### 2. FFmpeg（必需）
**Windows:**
1. 下载：https://ffmpeg.org/download.html
2. 解压到某个目录（如 `C:\ffmpeg`）
3. 添加到系统PATH：
   - 右键"此电脑" → 属性 → 高级系统设置 → 环境变量
   - 编辑 Path 变量，添加 `C:\ffmpeg\bin`
4. 验证安装：
   ```bash
   ffmpeg -version
   ```

**macOS:**
```bash
brew install ffmpeg
```

**Linux:**
```bash
sudo apt install ffmpeg  # Ubuntu/Debian
sudo yum install ffmpeg  # CentOS/RHEL
```

## 使用方法

### 启动程序
```bash
python compress_media.py
```

### 菜单选项

#### 选项 1: 🔍 扫描并压缩文件 (逐个处理模式)
**低磁盘占用模式**：每次只处理一个文件，立即释放临时空间。

处理流程：
1. 扫描源目录 `D:\.tmp\BaiduNetdiskDownload` 并计算总大小
2. 对每个文件执行：
   - 复制到 `_tmp` 临时目录
   - 压缩并保存到 `_compress` 目录
   - 验证压缩文件完整性
   - 立即删除 `_tmp` 中的临时文件
   - 更新JSON缓存
   - 继续下一个文件

**特性：**
- ✅ 低磁盘占用（只占用单个文件的临时空间）
- ✅ 实时显示压缩进度和效果
- ✅ **自动处理文件名空格**（自动将空格替换为下划线）
- ✅ **完整中文支持**（文件名、路径、输出均支持中文）
- ✅ 自动跳过已压缩的文件
- ✅ 检测重复文件（基于文件名）
- ✅ **智能断点续传**（详见 [RESUME_LOGIC.md](RESUME_LOGIC.md)）
  - 自动检测已压缩但未更新JSON的文件
  - 自动检测已复制但未压缩的文件
  - 自动删除并重新处理损坏的文件
- ✅ 显示实时累计压缩率和节省空间
- ✅ 视频和图片最大720P（不会放大）

#### 选项 2: 🔄 替换回源文件
将 `_compress` 目录中的压缩文件替换回原始位置。

**安全机制：**
- ⚠️ 替换前需要二次确认
- ✅ 自动备份原文件（.bak扩展名）
- ✅ 验证替换后的文件完整性
- ✅ 验证失败自动恢复原文件

**建议：**
在执行此操作前，先手动检查 `_compress` 目录中的文件，确认压缩效果满意。

#### 选项 3: 📊 查看统计信息
显示当前处理状态：
- 文件总数
- 各状态文件数量（已复制、已压缩、已替换等）
- 目录信息

#### 选项 0: 🚪 退出程序

## 目录结构

```
D:\.tmp\BaiduNetdiskDownload\
├── [原始文件]
│   ├── 视频1.mp4
│   ├── 图片1.jpg
│   └── 子目录/
│       └── 音频1.mp3
├── _tmp/                        # 临时目录（仅在处理单个文件时短暂存在）
│   └── [当前处理的文件]        # 处理完立即删除
├── _compress/                   # 压缩目录（压缩完成）
│   ├── 视频1.mp4
│   ├── 图片1.jpg
│   └── 子目录/
│       └── 音频1.mp3
└── compression_cache.json       # 缓存文件（记录处理状态）
```

**注意**：逐个处理模式下，`_tmp` 目录同时只会存在一个正在处理的文件，处理完成后立即删除。

## 缓存文件格式

`compression_cache.json` 记录所有文件的处理状态：

```json
{
  "version": "1.0",
  "last_update": "2024-01-15T10:30:00",
  "files": {
    "相对路径/文件名.mp4": {
      "type": "video",
      "source": "D:\\...\\文件名.mp4",
      "size": 1048576,
      "status": "compressed",
      "compressed_size": 524288,
      "compression_ratio": "50.0%",
      "compressed_at": "2024-01-15T10:25:00"
    }
  },
  "stats": {
    "total_files": 100,
    "compressed": 80,
    "skipped": 15,
    "failed": 5
  }
}
```

### 文件状态
- `copied` - 已复制到临时目录
- `compressed` - 已压缩完成
- `replaced` - 已替换回源文件
- `failed` - 处理失败

## 高级配置

编辑 `compress_media.py` 中的类常量：

```python
class MediaCompressor:
    # 图片设置
    IMAGE_MAX_DIMENSION = 720    # 最大分辨率
    IMAGE_MAX_SIZE_KB = 500      # 大小阈值
    IMAGE_QUALITY = 85           # JPEG质量 (0-100)

    # 视频设置
    VIDEO_CRF = 28              # 质量 (18-28, 越大压缩率越高)
    VIDEO_PRESET = 'medium'     # 速度 (ultrafast/fast/medium/slow)
    VIDEO_MAX_DIMENSION = 720   # 最大分辨率

    # 音频设置
    AUDIO_BITRATE = '128k'      # 比特率
```

## 注意事项

### ⚠️ 重要提示
1. **数据备份** - 操作前建议备份重要文件
2. **磁盘空间** - 逐个处理模式仅需单个文件的临时空间（约为最大文件大小）
3. **处理时间** - 大文件处理可能需要较长时间
4. **中断恢复** - 可以随时中断，下次继续处理
5. **验证结果** - 替换前务必验证压缩质量
6. **不会放大** - 视频和图片最大720P，小于此分辨率的不会放大

### 📝 最佳实践
1. 首次使用建议先在小范围测试
2. 压缩完成后先检查 `_compress` 目录
3. 确认无误后再执行替换操作
4. 定期备份 `compression_cache.json` 文件

### 🐛 常见问题

**Q: ffmpeg command not found**
A: 确保ffmpeg已安装并添加到系统PATH

**Q: PIL/Pillow导入失败**
A: 运行 `pip install Pillow`

**Q: 处理中断后如何继续？**
A: 直接重新运行程序，会智能恢复处理：
- 跳过已压缩完成的文件
- 检测已压缩但JSON未更新的文件（仅更新JSON）
- 检测已复制但未压缩的文件（跳过复制）
- 自动删除损坏的临时文件并重新处理
详见 [RESUME_LOGIC.md](RESUME_LOGIC.md)

**Q: 如何撤销替换操作？**
A: 如果替换失败，程序会自动恢复原文件。手动撤销需要从备份恢复。

**Q: 压缩率不理想怎么办？**
A: 调整配置参数（VIDEO_CRF越小质量越高但压缩率越低）

**Q: 文件名有空格会怎么样？**
A: 程序会自动将源文件名中的空格替换为下划线（_），多个连续空格合并为一个下划线。例如：
  - `My Video.mp4` → `My_Video.mp4`
  - `My   Video  File.mp4` （3个空格+2个空格）→ `My_Video_File.mp4`
  - 重命名后继续正常处理

**Q: 出现UnicodeDecodeError怎么办？**
A: v1.2已修复此问题，程序现在完整支持中文和特殊字符

## 技术细节

### 文件识别
- **图片**: .jpg, .jpeg, .png, .bmp, .gif, .webp, .tiff
- **视频**: .mp4, .avi, .mkv, .mov, .wmv, .flv, .webm, .m4v
- **音频**: .mp3, .wav, .flac, .aac, .ogg, .m4a, .wma

### 验证机制
- 图片: 使用PIL验证
- 视频/音频: 使用ffprobe验证
- 基本检查: 文件存在且大小>0

### 去重策略
仅对视频和音频文件进行去重：
- 比较文件名（不含路径）
- 相同文件名视为重复
- 跳过重复文件的压缩
