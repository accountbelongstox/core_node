=========================================
Codex MCP Configuration Manager - Usage Guide
=========================================

Reference: droid MCP management
Script: codex_sync_mcp_servers.py

This tool provides droid-style CLI commands for managing MCP (Model Context Protocol)
servers in Codex configuration (~/.codex/config.toml).

=========================================
1. Available Commands
=========================================

sync          - Sync MCP servers from OS-specific template
add           - Add new MCP server (HTTP or stdio)
remove        - Remove MCP server
list          - List all configured MCP servers
enable        - Enable a disabled MCP server
disable       - Disable an MCP server (without removing)
show-config   - Show Codex config path and current servers

=========================================
2. Sync from Template (Original Function)
=========================================

Sync MCP servers from template based on your OS:

Command:
  python codex_sync_mcp_servers.py sync

With working directory replacement:
  python codex_sync_mcp_servers.py sync --working-dir D:\programing\core_node

Features:
  - Auto-detects OS (Windows/WSL/Ubuntu Desktop/Linux Server)
  - Loads appropriate template file
  - Merges missing servers into your config
  - Creates backup before modification
  - Replaces $PROJECT_NAME$ placeholder

=========================================
3. Add HTTP MCP Servers
=========================================

Add remote MCP servers via HTTP/HTTPS endpoints:

Basic HTTP server:
  python codex_sync_mcp_servers.py add sentry https://mcp.sentry.dev/mcp --type http

With authentication headers:
  python codex_sync_mcp_servers.py add notion https://mcp.notion.com/mcp --type http --header "Authorization: Bearer your_token"

Multiple headers:
  python codex_sync_mcp_servers.py add custom-server https://example.com/mcp --type http \
    --header "Authorization: Bearer TOKEN" \
    --header "X-API-Key: your_api_key"

Popular HTTP Servers:
  # Sentry (Error monitoring)
  python codex_sync_mcp_servers.py add sentry https://mcp.sentry.dev/mcp --type http

  # Notion (Documentation)
  python codex_sync_mcp_servers.py add notion https://mcp.notion.com/mcp --type http

  # Linear (Project management)
  python codex_sync_mcp_servers.py add linear https://mcp.linear.app/mcp --type http

  # Stripe (Payments)
  python codex_sync_mcp_servers.py add stripe https://mcp.stripe.com --type http

  # Figma (Design)
  python codex_sync_mcp_servers.py add figma https://mcp.figma.com/mcp --type http

  # Vercel (Deployment)
  python codex_sync_mcp_servers.py add vercel https://mcp.vercel.com/ --type http

4. Add Stdio MCP Servers
=========================================

Add local process MCP servers:

Basic stdio server:
  python codex_sync_mcp_servers.py add my-server "node server.js"

With environment variables:
  python codex_sync_mcp_servers.py add airtable "npx -y airtable-mcp-server" \
    --env AIRTABLE_API_KEY=your_key

Multiple environment variables:
  python codex_sync_mcp_servers.py add clickup "npx -y @hauptsache.net/clickup-mcp" \
    --env CLICKUP_API_KEY=your_key \
    --env CLICKUP_TEAM_ID=your_team_id

Popular Stdio Servers:
  # Airtable
  python codex_sync_mcp_servers.py add airtable "npx -y airtable-mcp-server" \
    --env AIRTABLE_API_KEY=your_key

  # ClickUp
  python codex_sync_mcp_servers.py add clickup "npx -y @hauptsache.net/clickup-mcp" \
    --env CLICKUP_API_KEY=your_key \
    --env CLICKUP_TEAM_ID=your_team_id

  # HubSpot
  python codex_sync_mcp_servers.py add hubspot "npx -y @hubspot/mcp-server" \
    --env HUBSPOT_ACCESS_TOKEN=your_token

  # Filesystem (local access)
  python codex_sync_mcp_servers.py add filesystem "npx -y @modelcontextprotocol/server-filesystem" \
    --env ALLOWED_DIRECTORIES=/path/to/dir1,/path/to/dir2

  # Git operations
  python codex_sync_mcp_servers.py add git "npx -y @modelcontextprotocol/server-git"

  # Database (SQLite)
  python codex_sync_mcp_servers.py add sqlite "npx -y @modelcontextprotocol/server-sqlite" \
    --env DB_PATH=/path/to/database.db

=========================================
7. Enable/Disable Servers
=========================================

Temporarily disable a server (without removing):
  python codex_sync_mcp_servers.py disable notion

Re-enable a disabled server:
  python codex_sync_mcp_servers.py enable notion

Note: Disabled servers remain in config but won't be loaded by Codex

9. Configuration File Format
=========================================

Location:
  Windows: %USERPROFILE%\.codex\config.toml
  Linux/WSL: ~/.codex/config.toml

HTTP Server Example:
  [mcp_servers.notion]
  type = "http"
  url = "https://mcp.notion.com/mcp"

  [mcp_servers.notion.headers]
  Authorization = "Bearer your_token"

Stdio Server Example:
  [mcp_servers.airtable]
  command = "npx"
  args = ["-y", "airtable-mcp-server"]

  [mcp_servers.airtable.env]
  AIRTABLE_API_KEY = "your_key"

Disabled Server:
  [mcp_servers.notion]
  type = "http"
  url = "https://mcp.notion.com/mcp"
  disabled = true

10. Automatic Backups
=========================================

Every modification creates a timestamped backup:

Backup location:
  ~/.codex/.backups/config.backup.YYYYMMDD_HHMMSS.toml

Backup retention:
  - Keeps last 5 backups automatically
  - Older backups are cleaned up
  - Manual restoration possible if needed

Restore from backup:
  cp ~/.codex/.backups/config.backup.20251105_143022.toml ~/.codex/config.toml

11. Best Practices
=========================================

1. Use descriptive server names:
   ✓ python codex_sync_mcp_servers.py add notion-workspace https://mcp.notion.com/mcp --type http
   ✗ python codex_sync_mcp_servers.py add n1 https://mcp.notion.com/mcp --type http

2. Keep sensitive tokens in environment variables:
   ✓ --env API_KEY=$NOTION_API_KEY
   ✗ --env API_KEY=hardcoded_token_here

3. List servers regularly to review configuration:
   python codex_sync_mcp_servers.py list

4. Disable instead of remove for temporary testing:
   python codex_sync_mcp_servers.py disable server-name

5. Use sync for initial setup, add for custom servers:
   python codex_sync_mcp_servers.py sync        # First time
   python codex_sync_mcp_servers.py add ...     # Custom additions

13. Common Use Cases
=========================================

Use Case 1: Initial Setup
  1. Sync from template for your OS:
     python codex_sync_mcp_servers.py sync

  2. Review what was added:
     python codex_sync_mcp_servers.py list

  3. Add custom servers as needed:
     python codex_sync_mcp_servers.py add my-server "..." --env KEY=value

Use Case 2: Adding Cloud Service
  1. Find the MCP endpoint URL (check service docs)
  2. Add the server:
     python codex_sync_mcp_servers.py add service-name https://service.com/mcp --type http
  3. Add authentication if required:
     python codex_sync_mcp_servers.py add service-name https://service.com/mcp --type http \
       --header "Authorization: Bearer TOKEN"

Use Case 3: Local Development Tools
  1. Install local MCP server package:
     npm install -g @modelcontextprotocol/server-filesystem

  2. Add to Codex:
     python codex_sync_mcp_servers.py add filesystem "npx @modelcontextprotocol/server-filesystem" \
       --env ALLOWED_DIRECTORIES=/path/to/project

Use Case 4: Debugging
  1. List all servers to find issues:
     python codex_sync_mcp_servers.py list

  2. Disable problematic server:
     python codex_sync_mcp_servers.py disable problematic-server

  3. Test and re-enable when fixed:
     python codex_sync_mcp_servers.py enable problematic-server

=========================================
14. Troubleshooting
=========================================

Issue: Server not appearing in Codex
Solution:
  1. Verify it was added:
     python codex_sync_mcp_servers.py list
  2. Check it's not disabled
  3. Restart Codex/IDE
  4. Check Codex logs for errors

Issue: Authentication failing for HTTP server
Solution:
  1. Verify header format is correct (use quotes)
  2. Check token hasn't expired
  3. Use show-config to see current config path
  4. Manually verify in config.toml

Issue: Stdio server not starting
Solution:
  1. Test command manually in terminal
  2. Verify environment variables are set
  3. Check paths are absolute, not relative
  4. Review Codex server logs

Issue: Config changes not taking effect
Solution:
  1. Restart Codex CLI session
  2. Reload IDE/editor
  3. Check backup wasn't created (indicates save failure)
  4. Manually edit ~/.codex/config.toml if needed
