# 端口分配稳定性修复

## ✅ 已修复问题

### 原问题
端口号一直在变化，每次添加或删除应用，所有后续应用的端口都会改变。

### 根本原因
**之前的排序机制**：分段排序
1. 扫描 `apps/` 目录 → 按名称排序 → 分配端口 10000+
2. 扫描 `pyapps/` 目录 → 按名称排序 → 继续分配端口
3. 扫描 `poly_apps/` 目录 → 按名称排序 → 继续分配端口

**问题**：在 `apps/` 添加一个新应用，会导致所有 `pyapps/` 和 `poly_apps/` 的端口都往后移！

### 示例
```
添加 "aaa_new_app" 到 apps/ 目录前：
laravel_dashboard → 端口 10018

添加后：
aaa_new_app       → 端口 10000 (新增)
DevOps            → 端口 10001 (原来是 10000，往后移了)
...
laravel_dashboard → 端口 10019 (往后移了！)
```

---

## 🔧 修复方案：全局字母排序

### 代码修改
**文件**：`scripts/unified_manager/core/unified_core.py`
**位置**：Line 415-417 (新增3行)

```python
# 扫描所有应用后
for app_dir, app_type in app_dirs:
    apps = self.scanner.scan_directory(app_dir, app_type)
    self.apps.extend(apps)

# ✅ 新增：全局按名称排序
# 确保端口分配稳定，不会因为某个目录添加应用而影响其他目录
self.apps.sort(key=lambda x: x.name.lower())

# 分配端口
self.port_manager.assign_ports(self.apps)  # Port = 10000 + index
```

## 🎯 新的端口分配规则

### 原则
1. **所有应用按名称全局排序**（不区分 ncoreApp/pycoreApp/polyApp）
2. **端口 = 10000 + 字母顺序的索引**
3. **字母顺序不变，端口就不变**

### 示例
```
应用名                        字母顺序    端口
-----------------------------------------------
aaa_test (新增)               0          10000
cmg-corporate-portal          1          10001
d3-check                      2          10002
DevOps                        3          10003
flutter_bloom                 4          10004
...
laravel_dashboard             15         10015
```
