我理解了你的需求，让我说明我的设计方案：

  架构设计

  1. 目录结构

  scripts/build_scripts/
  ├── poly_app_manager.sh              # Linux启动脚本
  ├── poly_app_manager.ps1             # Windows启动脚本  
  ├── build_py_tools/
  │   ├── keys_center.py               # 键值中心（所有变量名定义）
  │   ├── project_detector.py          # 项目类型自动检测器
  │   ├── menu_system.py               # 交互式菜单系统
  │   ├── file_var_handler.py          # 文件变量读写处理器
  │   └── framework_configs.py         # 框架配置（动态生成菜单选项）

  2. 工作流程

  
  前置工作. 先了解dd.sh中的 Unified App Manager 如何集成。

  在 dd.sh 的 "Unified App Manager" 菜单中添加：
  5) Poly Apps Manager - 多项目管理器
     - 交互式启动所有poly_apps项目
     - 自动端口分配
     - 支持部署为系统服务

  阶段1：项目扫描（Python）

  1. 扫描 poly_apps/ 所有子目录
  2. 检测项目类型：
    - React Native: 检查 package.json 中是否有 react-native 依赖，查找
  android/ios 目录
    - Nuxt: 检查 nuxt.config.ts/js 或 package.json 中的 nuxt 依赖
    - Next.js: 检查 next.config.js 或 pages/app 目录
    - React+Vite: 检查 vite.config.js + react
    - Vue+Vite: 检查 vite.config.js + vue
    - Flutter: 检查 pubspec.yaml
    - Laravel: 检查 composer.json + artisan
  3. 自动分配端口（10000开始递增）
  4. 将结果写入文件变量（JSON格式）

  阶段2：菜单显示（Python）

  1. 读取扫描结果
  2. 根据项目类型动态生成菜单项：
    - Nuxt: [Debug|Build|Generate] → [Web|Deploy+反代（基于laravel Nginx管理）]
    - React Native: [Debug|Build|Release] → [Android|iOS|Web|Deploy+反代（基于laravel Nginx管理）]
    - Flutter: [Debug|Build|Release] → [Android|iOS|Web|Linux]
    - React/Vue: [Dev|Build|Preview] → [Web|Deploy+反代（基于laravel Nginx管理）]
  3. 使用 curses/blessed 实现箭头键导航
  4. 缓存用户上次选择（项目索引、功能索引、平台索引）
  5. 用户按Enter后，将选择写入文件变量

  阶段3：项目启动（Shell）

  1. Shell读取文件变量获取用户选择
  2. 切换到目标项目目录
  3. 设置环境变量（PORT等）
  4. 执行对应命令：
    - Debug模式: 启动dev server
    - Build模式: 执行构建
    - Deploy模式: 构建+以及调用laravel 命令服务

  3. 文件变量设计

  存储位置:
  - Linux: 查找 gvar common var sh脚本查看
  - Windows: 找到 GlobalVar 脚 本查看

  变量文件:
使用文件名一个文件名一个值 ，不使用json
