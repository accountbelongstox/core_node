程序的重复运行不会简单地把旧历史数据丢掉重装，而是按以下逻辑增量补齐：

  - 每个币先查 SQLite 的时间范围 get_time_range，并对已存数据做一次重复检查与去重。
  - 已有数据且覆盖 start_time（默认 3 天前）到当前时间前 1 小时：视为“Up‑to‑date”，只把 SQLite 里的数据重新加载到
    Redis，不再调用 OKX。
  - 如果覆盖不全，则根据缺口拉取：
      - 只差近期数据：从最新时间到当前时间补“gap”；
      - 只差早期数据：从 start_time 到最早时间补“gap”；
      - 早期+近期都缺：整段重拉。
  - 获取到的新蜡烛先写 SQLite（INSERT OR REPLACE），再把所需范围加载到 Redis。Redis 不持久化，但每次启动都会从 SQLite
    装载，因此不会产生“空白历史”。
  - 你目前运行用的是内存 fallback Redis；即便如此，历史仍来自 SQLite，不会缺段。如果希望减少 API 调用，可以在 SQLite
    数据已覆盖时直接满足启动需求。

  简而言之：历史数据装载成功后再次启动，只有时间缺口会被补齐，已有完整数据会直接复用。
