2. 客户端库HTTP访问 ✓
   - 地址: GET /rpc/client.js
   - 浏览器引用: <script src="/rpc/client.js"></script>
   - 自动提供 UnifiedRpcClient.js

3. 客户端连接与ID管理 ✓
   - 客户端创建 clientId (UUID)
   - 每个请求生成 requestId (UUID)
   - 服务端根据 clientId 创建 session
   - 服务端将 session 添加到 group

4. 回调机制 ✓
   - 服务端根据 requestId 创建回调
   - 后端逻辑完成后调用回调
   - 数据通过回调返回

5. WebSocket 通知机制 ✓
   - 直接通知客户端
   - 失败后重试 3 次
   - 每次间隔 1 秒
   - 3次失败后存入缓存

6. HTTP 缓存机制 ✓
   - 缓存时间：30 分钟
   - 缓存池大小：10000 条
   - 超过限制删除最旧条目
   - 自动清理过期条目

7. 统一客户端 ✓
   - 同时支持 WebSocket 和 HTTP
   - WebSocket 优先策略
   - WebSocket 连接成功后不用 HTTP
   - HTTP 自动 fallback

8. 客户端查询策略 ✓
   - 发起连接时准备 requestId 查询
   - WebSocket: 接收通知，区分消息类型
     * RESPONSE: 结果回调
     * EVENT: 事件通知
     * ERROR: 错误处理
   - HTTP: 提交后每 1.5 秒查询一次
   - 超时时间：30 秒

9. 子应用集成机制 ✓ 【NEW】
   - 子应用可以注册到RPC框架
   - 配置覆盖：子应用config覆盖原配置
   - 静态路径添加：子应用可添加自己的静态目录
   - 路由注册：子应用注册路由和处理函数
   - **结果统一管理：所有结果返回RPC框架，按requestId回调**
   - 自动路由前缀：AppName.routeName
   - 透明集成：WebSocket重试、HTTP缓存对子应用透明
   - 使用方法：
     ```javascript
     rpc.registerSubApp('AppName', {
         config: { CUSTOM_TIMEOUT: 5000 },
         staticPaths: { '/app-static': '/path/to/static' }
     });

     rpc.registerRoute('AppName', 'getData', async (params, context) => {
         // context.requestId - 请求ID
         // context.appName - 应用名称
         const result = await processData(params);
         return result; // 返回给RPC框架统一管理
     });

     // 客户端调用
     const result = await client.call('AppName.getData', params);
     ```

配置完整示例：
=============

// 服务端配置
const rpc = require('#@ncore/utils/rpc');

const server = rpc.createExpressServer({
    HTTP_PORT: 8080,
    HTTP_HOST: '0.0.0.0',
    WS_PORT: 8080,
    USE_SAME_PORT: true,

    REQUEST_TIMEOUT: 30000,
    MAX_PAYLOAD_SIZE: 10485760,

    CACHE_TTL: 1800000,      // 30 分钟
    CACHE_MAX_SIZE: 10000,

    STATIC_PATHS: {
        '/static': [
            '/path/to/public',
            '/path/to/static'
        ],
        '/assets': '/path/to/assets'
    }
});

// 注册 RPC 路由
const rpcServer = rpc.createHttpServer(server.getApp());

rpcServer.route('routeName', async (params) => {
    // 处理逻辑
    return { result: 'data' };
});

rpcServer.start();
await server.start();

// 客户端配置 (Node.js)
const client = rpc.createClient('http://localhost:8080/rpc', {
    clientId: 'optional-id',      // 可选，自动生成
    timeout: 30000,               // 30秒超时
    httpPollInterval: 1500,       // HTTP 轮询间隔 1.5秒
    httpFallback: true,           // 启用 HTTP fallback
    reconnect: true,              // 自动重连
    reconnectInterval: 3000,      // 重连间隔 3秒
    maxReconnectAttempts: 10      // 最多重连 10 次
});

// 客户端配置 (浏览器)
<script src="/rpc/client.js"></script>
<script>
const client = new UnifiedRpcClient('http://localhost:8080/rpc', {
    clientId: 'browser-client',
    httpFallback: true
});

client.on('connected', (data) => {
    console.log('Connected via', data.mode);
});

const result = await client.call('routeName', { param: 'value' });
</script>

完整流程验证：
=============

场景 1: WebSocket 成功通知
1. 客户端生成 clientId 和 requestId
2. 客户端通过 WebSocket 连接服务端
3. 客户端发送 init 消息 {type: 'init', clientId}
4. 服务端创建 session 并添加到 group
5. 客户端发送请求 {type: 'request', id: requestId, route, params}
6. 服务端执行处理
7. 服务端通过 WebSocket 直接发送响应 (1次成功)
8. 客户端立即收到响应

场景 2: WebSocket 重试机制
1. 客户端生成 clientId 和 requestId
2. 客户端通过 WebSocket 连接服务端
3. 服务端执行处理完成
4. 服务端尝试发送 (attempt 1/3) - 失败
5. 等待 1 秒
6. 服务端尝试发送 (attempt 2/3) - 失败
7. 等待 1 秒
8. 服务端尝试发送 (attempt 3/3) - 失败
9. 服务端将响应存入缓存 (30分钟 TTL)
10. 客户端可通过 HTTP 查询获取

场景 3: HTTP 轮询模式
1. 客户端生成 clientId 和 requestId
2. 客户端 WebSocket 连接失败
3. 客户端切换到 HTTP 模式
4. 客户端 POST /rpc {type: 'request', id: requestId, route, params}
5. 服务端创建 session 并添加到 group
6. 服务端执行处理
7. 服务端缓存响应
8. 服务端返回 202 或结果
9. 客户端开始轮询 GET /rpc/query/:requestId (每 1.5秒)
10. 服务端返回缓存结果
11. 客户端收到响应，轮询停止

场景 4: 静态文件访问
1. 配置 STATIC_PATHS: {'/static': ['/dir1', '/dir2']}
2. 客户端访问 GET /static/file.txt
3. 服务端依次在 /dir1, /dir2 中查找
4. 找到文件后返回
5. 浏览器访问 GET /rpc/client.js 获取客户端库
