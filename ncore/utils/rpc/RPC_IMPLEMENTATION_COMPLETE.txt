核心流程已完整实现：
=====================

1. 客户端连接流程
   ✓ 客户端创建 clientId (UUID)
   ✓ 客户端发送 init 消息包含 clientId
   ✓ 服务端根据 clientId 创建 session
   ✓ 服务端将 session 添加到 group (按 clientId 分组)
   ✓ 每次请求生成独立的 requestId (UUID)

2. 请求处理流程
   ✓ 客户端发送请求时携带 clientId 和 requestId
   ✓ 服务端根据 clientId 查找/创建 session
   ✓ 服务端将 session 添加到对应的 clientId 组
   ✓ 服务端执行路由处理函数
   ✓ 服务端根据 requestId 准备响应

3. WebSocket 响应通知机制 (已实现重试)
   ✓ 服务端完成处理后，尝试通过 WebSocket 直接通知
   ✓ 如果发送失败，重试最多 3 次
   ✓ 每次重试间隔 1 秒
   ✓ 3 次都失败后，将响应存入缓存

4. HTTP 响应缓存机制
   ✓ WebSocket 通知失败后，响应自动缓存
   ✓ 缓存时间：30 分钟 (1800000ms)
   ✓ 缓存大小限制：10000 条
   ✓ 超过限制时删除最旧的条目
   ✓ 自动清理过期条目（每 60 秒）

5. 客户端查询机制
   ✓ 客户端支持 WebSocket 和 HTTP 双模式
   ✓ 优先尝试 WebSocket 连接
   ✓ WebSocket 连接成功后不使用 HTTP
   ✓ WebSocket 连接失败时自动 fallback 到 HTTP
   ✓ HTTP 模式：提交后每 1.5 秒轮询查询结果
   ✓ 查询端点：GET /rpc/query/:requestId
   ✓ 查询到结果后自动从缓存移除

6. 消息类型区分
   ✓ 客户端接收 WebSocket 消息时区分类型：
     - RESPONSE: 响应结果
     - EVENT: 事件通知
     - ERROR: 错误消息
   ✓ 根据消息类型调用不同的处理逻辑

实现细节：
=========

WebSocket 服务端 (WsRpcServer.js):
- 使用共享的 sessionManager 管理会话和分组
- 使用共享的 requestManager 跟踪请求
- 使用共享的 responseCache 缓存响应
- _sendResponseWithRetry() 实现重试逻辑：
  * 最多重试 3 次
  * 每次间隔 1000ms
  * 失败后缓存到 responseCache

HTTP 服务端 (HttpRpcServer.js):
- 使用相同的 sessionManager, requestManager, responseCache
- POST /rpc 接收请求
- GET /rpc/query/:requestId 提供查询接口
- 响应自动缓存 30 分钟

统一客户端 (UnifiedRpcClient.js):
- 支持浏览器和 Node.js 环境
- 自动生成 clientId 或使用提供的 clientId
- 每个请求生成唯一的 requestId
- WebSocket 优先策略
- HTTP fallback 机制
- HTTP 轮询间隔：1500ms (1.5 秒)
- 请求超时：30000ms (30 秒)

数据流程图：
===========

客户端 → 服务端（WebSocket成功）:
1. Client: 生成 clientId, requestId
2. Client → Server: WebSocket 连接 + init 消息
3. Server: 创建 session, 添加到 group
4. Client → Server: 发送请求 (route, params, clientId, requestId)
5. Server: 执行处理
6. Server → Client: 直接通过 WebSocket 返回结果 ✓
7. Client: 立即收到响应

客户端 → 服务端（WebSocket失败）:
1. Client: 生成 clientId, requestId
2. Client → Server: WebSocket 连接失败
3. Client: 切换到 HTTP 模式
4. Client → Server: POST /rpc (route, params, clientId, requestId)
5. Server: 创建 session, 添加到 group
6. Server: 执行处理
7. Server: 缓存响应到 responseCache
8. Server → Client: 返回 202 或结果
9. Client: 开始轮询 GET /rpc/query/:requestId (每 1.5 秒)
10. Server → Client: 返回缓存的结果
11. Client: 收到响应

WebSocket 重试流程:
1. Server: 执行完成，准备返回结果
2. Server: 尝试发送 (attempt 1/3)
3. 如果失败: 等待 1 秒
4. Server: 尝试发送 (attempt 2/3)
5. 如果失败: 等待 1 秒
6. Server: 尝试发送 (attempt 3/3)
7. 如果仍失败: 缓存到 responseCache
8. Client: 可通过 HTTP 查询获取结果
