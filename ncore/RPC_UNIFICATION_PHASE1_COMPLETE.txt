USAGE PATTERNS
=============================================================================

Pattern 1: WebSocket RPC Only (Standalone)
-------------------------------------------
const { WsRpcServer } = require('#@ncore/utils/ws_rpc');

const server = new WsRpcServer({ port: 3000 });
await server.start();
server.route('myMethod', handler);


Pattern 2: WebSocket RPC Attached to Express
---------------------------------------------
const expressUtils = require('#@ncore/foundation/express_utils');
const { WsRpcServer } = require('#@ncore/utils/ws_rpc');

await expressUtils.startExpressServer({ HTTP_PORT: 3000 });
const wss = expressUtils.getWebSocketServer();

const wsRpc = new WsRpcServer(wss);
await wsRpc.start();
wsRpc.route('myMethod', handler);


Pattern 3: HTTP RPC Only
-------------------------
const express = require('express');
const { HttpRpcServer } = require('#@ncore/utils/http_rpc');

const app = express();
app.use(express.json());

const httpRpc = new HttpRpcServer(app);
httpRpc.start();
httpRpc.route('myMethod', handler);

app.listen(3000);


Pattern 4: Unified WebSocket + HTTP RPC (RECOMMENDED)
------------------------------------------------------
const expressUtils = require('#@ncore/foundation/express_utils');
const { WsRpcServer } = require('#@ncore/utils/ws_rpc');
const { HttpRpcServer } = require('#@ncore/utils/http_rpc');

// Start Express with WebSocket
await expressUtils.startExpressServer({ HTTP_PORT: 3000 });

// Get instances
const wss = expressUtils.getWebSocketServer();
const app = expressUtils.getConfig().app;

// Setup both transports
const wsRpc = new WsRpcServer(wss);
const httpRpc = new HttpRpcServer(app);

await wsRpc.start();
httpRpc.start();

// Register same handler for both
const handler = async (params, clientId) => { /* ... */ };
wsRpc.route('translateText', handler);
httpRpc.route('translateText', handler);

// Clients can use either:
// - ws://localhost:3000 (WebSocket)
// - http://localhost:3000/rpc (HTTP)

=============================================================================
BENEFITS
=============================================================================

1. FLEXIBILITY
   - Deploy WebSocket only, HTTP only, or both
   - Choose transport based on requirements
   - No architectural changes needed

2. CONSISTENCY
   - Same RPC protocol across transports
   - Same message format (REQUEST/RESPONSE/EVENT)
   - Same error codes and status constants

3. CODE REUSE
   - Share handlers between WebSocket and HTTP
   - Reuse managers (Auth, RateLimit, Performance)
   - Single business logic, multiple transports

4. COMPATIBILITY
   - WebSocket: Real-time, bidirectional, persistent
   - HTTP: Stateless, firewall-friendly, REST-like
   - Support clients with different capabilities

5. NO BREAKING CHANGES
   - Existing ws_rpc code continues to work
   - Existing express_utils code continues to work
   - Opt-in integration when needed

=============================================================================
TRANSPORT COMPARISON
=============================================================================

WebSocket RPC:
  ✓ Real-time bidirectional communication
  ✓ Server can push events to clients
  ✓ Persistent connection (lower overhead)
  ✓ Built-in heartbeat monitoring
  ✓ Namespace and room support
  ✗ Requires WebSocket support
  ✗ May have firewall issues

HTTP RPC:
  ✓ Stateless request-response
  ✓ Firewall-friendly
  ✓ REST-like familiarity
  ✓ Standard HTTP tooling
  ✓ Batch request support
  ✗ No server push (polling needed)
  ✗ Higher overhead per request

RECOMMENDATION:
- Use WebSocket for real-time features
- Use HTTP for stateless operations
- Use both for maximum flexibility
