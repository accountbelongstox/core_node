# YOLO Data Management UI Design Document

Complete UI redesign for YOLO data management area, aligned with GameAISDK workflow and data model.

**Reference**: GameAISDK `doc/YOLO/TrainDetModel.md`, `doc/SDKTool/PyLibUsage.md`, `doc/SDKTool/UIAutoExplore.md`, `Modules/darknetV3/src/scripts/voc_label.py`.

---

## 0. GameAISDK Labeling and Project–Annotation Model

### 0.1 Labeling tool and format (TrainDetModel.md)

- **Tool**: **labelImg** (https://github.com/tzutalin/labelImg). GameAISDK doc does not bundle labelImg; user runs `python labelImg.py` and sets:
  - **打开目录**: image folder (e.g. segment `frames/` or merged folder).
  - **改变存放目录**: where to save VOC XML files (can be same as image folder or a separate Annotations folder).
- **Output**: One **VOC XML** per image. Each XML has `<annotation>` with `<filename>`, `<size>`, and one or more `<object>` with `<name>` (class) and `<bndbox>` (xmin, ymin, xmax, ymax). One image can have **multiple objects** (multiple labels).
- **Classes**: labelImg uses a predefined class list (e.g. `data/predefined_classes.txt`). **One labeling dataset must use one consistent class list**; VOC→YOLO conversion (`voc_label.py`) uses the same `classes` list for `voc.names` and indexing.

### 0.2 Project vs dataset vs annotations

- **Recording project**: One root path (SavePath) → many **segments** (`output/<timestamp>/`). Each segment is one recording session; may contain `video.avi` or `.jpg` + `data.csv`, and after export a `frames/` subdir.
- **Labeling dataset**: One logical set of images to be labeled together with **one class list**. It can be:
  - **Single-segment**: one segment’s `frames/` directory.
  - **Merged**: multiple segments exported into one folder (e.g. via “Merge selected”) so that all frames are in one place for one labelImg session.
- **Annotations**: In YOLO/VOC flow, each image has zero or one XML file (same base name, `.xml`). “Labeled” = presence of XML (or YOLO `.txt`) for that image. Multiple **objects** inside one XML = multiple boxes/labels on one image.
- **Relationship**: One **project** has many **segments**. One **dataset** (for labeling) = one folder of images + one folder (or same folder) of XMLs + one **classes** list. Multiple segments can feed **one dataset** (merge → label once with one class list).

### 0.3 VOC layout and voc_label (TrainDetModel §5–6)

- **VOCdevkit/VOC2007/** (or year): `Annotations/` (XML), `JPEGImages/` (images), `ImageSets/Main/` (`train.txt`, `val.txt`, `test.txt` — list of image_id per line), `labels/` (YOLO `.txt` per image, generated by `voc_label.py`).
- **voc_label.py** (GameAISDK `Modules/darknetV3/src/scripts/voc_label.py`): Reads `classes`, reads each XML from `Annotations/`, writes YOLO-format `.txt` to `labels/`; expects image list from `ImageSets/Main/*.txt`. **Classes** must match across voc_label.py, voc.names, and cfg.
- **Clean step (DelUnLabelImg)**: Before or alongside VOC, remove images that have no XML and XMLs that have no image, so that image set and annotation set are in 1:1 correspondence.

### 0.4 UI implications

- **Classes**: For a given dataset (single segment or merged), the UI should support or surface the **class list** used for labeling and training (e.g. link to edit voc.names / predefined_classes, or show “Current classes”).
- **Open for labeling**: Opens the **image directory** (frames/ or merged folder) in explorer; user then starts labelImg, sets “打开目录” to that folder and “存放目录” to same folder or to a chosen Annotations path. Optionally, UI can offer “Launch labelImg” with image dir (and optionally default save dir) if labelImg is on PATH or configured.
- **Labeled status**: A segment (or merged folder) is considered **labeled** when the image directory contains at least one VOC XML (or YOLO txt). Status “Labeled” in the table = `segment_has_labeled(segment_path)` (e.g. `.xml` or `.txt` in `frames/`).
- **Merge selected**: Produces **one dataset** (one folder). User labels that folder once with one class list; that dataset can later be exported to VOC layout and passed to voc_label.py for training.

## 1. Design Principles

### 1.1 Workflow-Oriented
- Organize UI by YOLO training flow: **Record → Export Frames → Label → Train**
- Each step should be clearly visible and accessible
- Show progress/status for each segment through the pipeline

### 1.2 Information Hierarchy
- **Top**: Project context (current project, quick actions)
- **Middle**: Segment list (main data view)
- **Bottom**: Batch operations (toolbar grouped by workflow step)

### 1.3 Visual Feedback
- Use color coding for segment status: raw (gray) → exported (blue) → labeled (green)
- Icons or badges for quick status recognition
- Disable operations when prerequisites not met

### 1.4 Multi-Segment Support
- Multi-select for batch operations
- Clear indication of selected segments
- Merge operation prominently placed for combining segments

### 3.2 Workflow Status Bar

**Layout**:

**Components**:

### 3.3 Segment Table

**Purpose**: Main data view showing all segments with status and actions

**Columns**:

| Column | Width | Content | Format |
|--------|-------|---------|--------|
| **Select** | 30px | Checkbox | ☑ / ☐ (multi-select) |
| **Timestamp** | 180px | Segment timestamp | `YYYY-MM-DD HH:MM:SS` |
| **Frames** | 80px | Frame count or indicator | `120` / `video` / `-` |

**Status Values**:
- **Raw**: Has `video.avi` or `.jpg` files, no `frames/` directory

**Visual Indicators**:

**Labeled status (per GameAISDK)**: Segment is “Labeled” when `frames/` contains at least one `.xml` (VOC) or `.txt` (YOLO). One image → one annotation file; one annotation file can contain multiple objects.

### 3.4 Action Toolbar

**Purpose**: Batch operations grouped by workflow step

**Layout**:
```
[Refresh] | [Export Selected] [Open Label] | [Merge Selected] | [Delete Selected]
```

**Grouping**:
- **Group 1**: Refresh (data operations)
- **Group 2**: Step 2 operations (Export, Open Label)
- **Group 3**: Step 3 operations (Merge - combines multiple segments)
- **Group 4**: Management (Delete)

**Buttons**:

1. **Refresh**
   - Reload segment list from current project
   - Updates workflow status bar
   - i18n: `yolo_data_refresh`

2. **Export Selected**
   - For each selected segment: `compose_segment_to_frames`
   - Opens first exported `frames/` directory
   - Requires: at least one segment selected
   - i18n: `yolo_data_export_selected`

3. **Open Label**
   - First selected segment: ensure frames exported, open `frames/` in explorer
   - Requires: at least one segment selected
   - i18n: `yolo_data_open_label`

4. **Merge Selected**
   - Choose target folder via dialog
   - Export each selected segment's frames into target with prefix `seg_0_`, `seg_1_`, ...
   - Open merged folder for labeling
   - Requires: at least two segments selected
   - i18n: `yolo_data_merge_selected`

5. **Delete Selected**
   - Delete all selected segment directories
   - Confirmation dialog: "Delete X segments? This cannot be undone."
   - Disabled when recording
   - Requires: at least one segment selected
   - i18n: `yolo_data_delete_selected`

**Visual**:
- Group separators: `|` or visual spacing
- Disabled state: grayed out when prerequisites not met
- Tooltips: explain what each button does

## 4. Interaction Flow

### 4.1 Typical Workflow

1. **User starts recording** → New segment appears in table (Status: Raw)
2. **User stops recording** → Segment saved, table refreshes
3. **User selects segment(s)** → Checkboxes checked, buttons enabled
4. **User clicks "Export Selected"** → Frames extracted, Status changes to Exported
5. **User clicks "Open Label"** → Explorer opens with frames directory
6. **User labels images** (external tool) → Status changes to Labeled (future)
7. **User selects multiple segments** → Clicks "Merge Selected" → All frames merged into one folder

### 4.2 Multi-Segment Merge Flow

1. User selects 3 segments (Ctrl+Click)
2. Clicks "Merge Selected"
3. Dialog: "Select folder for merged frames"
4. User chooses `D:/merged_dataset/`
5. System:
   - Exports segment 1 → `D:/merged_dataset/seg_0_frame_000000.png`, ...
   - Exports segment 2 → `D:/merged_dataset/seg_1_frame_000000.png`, ...
   - Exports segment 3 → `D:/merged_dataset/seg_2_frame_000000.png`, ...
6. Explorer opens `D:/merged_dataset/`
7. User labels all frames in one go

## 5. State Management

### 5.1 Segment Status Detection

**Raw**:
```python
has_video = os.path.isfile(os.path.join(segment_path, "video.avi"))
has_jpg = any(f.endswith(".jpg") for f in os.listdir(segment_path))
has_frames = os.path.isdir(os.path.join(segment_path, "frames"))
status = "raw" if (has_video or has_jpg) and not has_frames else ...
```

**Exported**:
```python
has_frames = os.path.isdir(os.path.join(segment_path, "frames"))
frames_count = len([f for f in os.listdir(frames_dir) if f.endswith((".jpg", ".png"))])
status = "exported" if has_frames and frames_count > 0 else ...
```

**Labeled** (future):
```python
# Check for XML files (VOC format) or txt files (YOLO format)
has_xml = any(f.endswith(".xml") for f in os.listdir(frames_dir))
has_txt = any(f.endswith(".txt") for f in os.listdir(frames_dir))
status = "labeled" if (has_xml or has_txt) else ...
```

### 5.2 Directory Size Calculation

```python
def get_directory_size(path):
    total = 0
    for dirpath, dirnames, filenames in os.walk(path):
        for f in filenames:
            fp = os.path.join(dirpath, f)
            total += os.path.getsize(fp)
    return total  # bytes
```

Format: `"{:.1f} MB".format(size / 1024 / 1024)`

## 10. Flow Requirements (from GameAISDK and docs/yolo_train_flow.md)

The UI and backend must support the following pipeline; details are in `docs/yolo_train_flow.md`.

| Step | Requirement | UI / API |
|------|-------------|----------|
| 1 Record | Config, Start, Stop, New segment; output = project `output/<timestamp>/`. | Record row; `yolo_record.run_gameaisdk_start_record`, `stop_record`, `start_record_segment`, `end_record_segment`. |
| 2 Export | Segment (video or jpg) → `frames/` with images. | Export selected; `compose_segment_to_frames`. Merge = multiple segments → one folder (one dataset). |
| 3 Label | User labels images with **labelImg** (or equivalent). 打开目录 = image dir, 存放目录 = XML save dir. **One class list per dataset.** | Open for labeling = open image dir; optional “Launch labelImg” with dirs. Show/set classes for dataset (future). |
| 4 Clean (optional) | Remove images without XML and XML without image (DelUnLabelImg logic). | Optional “Clean unlabeled” on segment or merged folder; API e.g. `clean_unlabeled(image_dir, label_dir)`. |
| 5 VOC→YOLO | Build VOCdevkit layout; run `voc_label.py` with **classes**; output `labels/*.txt`, train.txt. | Optional “Export to VOC” / “VOC to YOLO”; reference GameAISDK `Modules/darknetV3/src/scripts/voc_label.py`. |
| 6 Train | voc.names, voc.data, yolov3-voc.cfg; darknet detector train. | Optional config path + “Start train”; reference GameAISDK darknet. |

**Classes**: One dataset (one folder of images + labels) must use one consistent **classes** list for labelImg, voc_label.py, voc.names, and cfg. UI may show “Classes” for current project/dataset or link to edit; merge does not change class list (user ensures consistency).
