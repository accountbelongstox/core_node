# 「两条线」的十种可能含义

针对：C4 识图结果「未匹配，游戏掉线」→ 增加节点「识别到掉线」→ 连到 [F1c] 结束 D3 进程。  
你要的是「两条线」，不是「一条线中间多一个节点」。下面列出十种可能，你指认是哪一种（或哪几种组合）。

---

## 1. F1c 有两条入边（两个不同来源都指向 F1c）

- **第一条线**：C4 未匹配游戏掉线 → [F1d] 识别到掉线 → F1c  
- **第二条线**：另一处（如 C10 悬赏视为掉线）→ F1c  
- 图上体现：F1c 有两个箭头指进来。  
- 当前图：已有一条 F1d→F1c、一条 C10→F1c。

---

## 2. 两条边在结构上分属两个 subgraph（C 里一条、F 里一条）

- **第一条线**：完全在 C 内，例如 C4 → 某节点（该节点仍在 C）。  
- **第二条线**：完全在 F 内，例如 某节点 → F1c（该节点在 F）。  
- 不在 C→F 之间画「一条跨区的线」，而是 C 内一段 + F 内一段，两段分开写。

---

## 3. 两个并列的「掉线」节点，都连到 F1c

- **第一条线**：C4 未匹配游戏掉线 → 节点 A（如「识图掉线」）→ F1c。  
- **第二条线**：C4 或别处 → 节点 B（如「悬赏掉线」）→ F1c。  
- A、B 是不同节点，两条独立路径进 F1c。

---

## 4. 从 C4 出发的两条不同路径，最终都到 F1c

- **第一条线**：C4 → |未匹配，游戏掉线| → [F1d] → F1c。  
- **第二条线**：C4 → |未匹配，进入 D| → … → 某步再 → F1c（或 C4 的另一个分支最终也到 F1c）。  
- 强调：到 F1c 有两条「从 C4 开始」的路径，而不是一条。

---

## 5. 同一对节点之间画两条箭头（两条边）

- 例如：C4 到 F1c 有两条不同的连线（两条边），一条标「未匹配，游戏掉线」，另一条标别的含义。  
- 或：[F1d] 到 F1c 画两条箭头，表示两种不同情况都走「结束 D3」。

---

## 6. 两条线 = 两个动作/步骤（先「识别掉线」再「结束 D3」）

- **第一条线**：表示「识别到掉线」这一步（C4 → 某节点，或 C4→F1d）。  
- **第二条线**：表示「执行结束 D3」这一步（该节点 → F1c）。  
- 图上用两个框 + 两条边明确分出「判定」和「执行」，不能合并成一步。

---

## 7. 视觉上两条不共线的线段（拐开画）

- 不在一条直线上画 C4→F1d→F1c，而是通过布局/subgraph 让「C4→F1d」和「F1d→F1c」在图上拐开，看起来是两段线。  
- 实现方式：把 F1d 放进单独 subgraph，或调整节点顺序，让渲染出来是两段折线。

---

## 8. 用两种线型区分（如实线 / 虚线）

- **第一条线**：实线，例如 C4 → [F1d]（识图掉线）。  
- **第二条线**：虚线，例如 [F1d] → F1c（结束 D3）。  
- Mermaid 里用 `-->` 与 `-.->` 区分，在注释里写明「第一条线」「第二条线」。

---

## 9. 两条线 = 两个不同「掉线」来源，都先到一个汇总节点再连 F1c

- **第一条线**：C4 未匹配游戏掉线 → 汇总节点（如「所有掉线」）。  
- **第二条线**：C10 悬赏视为掉线 → 同一汇总节点。  
- 汇总节点 → F1c（只一条出边）。这样「两条线」指进汇总节点的两条入边。

---

## 10. 两条线 = 两个并列的「结束 D3」入口，都写进图例/说明

- 在图外说明或图例里写：  
  - 第一条线：C4 识图未匹配、游戏掉线 → [F1d] 识别到掉线 → [F1c] 结束 D3。  
  - 第二条线：（你指定的另一种场景）→ [F1c] 结束 D3。  
- 图里保证 F1c 的入边和节点与说明一致，用文档明确「两条线」的定义。
