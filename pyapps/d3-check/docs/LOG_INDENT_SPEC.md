# 日志行首缩进规范（LOG_INDENT_SPEC）

日志文件路径由 `providor.providor_index.LOGS_FILE_PATH` 提供，默认 `Documents/RoS-BoT/Logs/history.txt`。行首的 TAB 与空格用于分块：**0 缩进 = 新日志条；正缩进 = 上一条的续行**（如异常堆栈）。

实现与检测见 `d3utils.log_indent_spec`。

---

## 一、每种特性的说明

### 1. TAB（制表符）

| 特性 | 说明 |
|------|------|
| 字符 | `\t` (U+0009) |
| 用途 | 行首连续 TAB 数表示“块层级”。当前 ROSBOT 日志中未使用行首 TAB，均为 0。 |
| 分块 | 行首 TAB 数减少或为 0 时视为新块开始。 |

### 2. 普通空格（SPACE）

| 特性 | 说明 |
|------|------|
| 字符 | 普通空格 U+0020 (SPACE) |
| 用途 | 行首连续空格数表示续行缩进。如 3 个空格表示“堆栈帧”续行（`   at ...`）。 |
| 分块 | 0 个空格 = 新日志行（带时间戳的 INFO/WARN 等）；大于 0 = 归属上一条的续行。 |

### 3. 特殊空格（检测但不一定出现）

以下 Unicode 空白字符在检测中会单独统计；若出现在行首会计入对应“空格组件”。当前 1000 行样本中**仅出现 U+0020**。

| 代码点 | 名称 | 说明 |
|--------|------|------|
| U+0020 | SPACE | 普通空格，唯一在样本中出现的行首空格。 |
| U+00A0 | NO-BREAK SPACE | 不换行空格，与 U+0020 视觉相似。 |
| U+1680 | OGHAM SPACE | 欧甘空格。 |
| U+2000 | EN QUAD |  en 宽空格。 |
| U+2001 | EM QUAD |  em 宽空格。 |
| U+2002 | EN SPACE |  en 空格。 |
| U+2003 | EM SPACE |  em 空格。 |
| U+2004 | THREE-PER-EM SPACE | 1/3 em 宽。 |
| U+2005 | FOUR-PER-EM SPACE | 1/4 em 宽。 |
| U+2006 | SIX-PER-EM SPACE | 1/6 em 宽。 |
| U+2007 | FIGURE SPACE | 数字等宽空格。 |
| U+2008 | PUNCTUATION SPACE | 标点宽度空格。 |
| U+2009 | THIN SPACE | 细空格。 |
| U+200A | HAIR SPACE | 极细空格。 |
| U+202F | NARROW NO-BREAK SPACE | 窄不换行空格。 |
| U+205F | MEDIUM MATHEMATICAL SPACE | 数学中等空格。 |
| U+3000 | IDEOGRAPHIC SPACE | 表意空格（全角）。 |
| U+FEFF | ZERO WIDTH NO-BREAK (BOM) | 零宽不换行 / BOM，可能出现在文件头。 |

其他由 `str.isspace()` 判定的空白字符会以 `U+XXXX` 形式计入，便于发现未知特殊空格。

---

## 二、状态定义（与空格组件的对应）

**状态** = 行首的 `(tabs, 空格组件)` 的规范表示。

- **tabs**：行首连续 TAB 的个数。
- **空格组件**：行首连续空白中，按“字符类型”统计的个数，键为 `U+XXXX`，值为该类型字符个数。仅包含在行首实际出现的类型；未出现的类型在状态键中不写（逻辑上等价于 0）。

状态键格式：`tabs=N, U+0020=M, U+00A0=K, ...`（按码点排序）。例如：

- `tabs=0, U+0020=0`：无 TAB、无行首空格 → 新日志行。
- `tabs=0, U+0020=3`：无 TAB、3 个普通空格 → 续行（如堆栈 `   at ...`）。

---

## 三、1000 行日志中出现的所有状态

样本：前 1000 条非空行；路径：`Documents/RoS-BoT/Logs/history.txt`。

### 3.1 统计汇总

- **分析行数**：1000
- **出现的空格组件类型**：`U+0020`（仅普通空格）
- **出现的 TAB 层级**：`0`（无行首 TAB）
- **不同状态数**：2

### 3.2 各状态及与空格组件、行类型

| 状态键 | 行数 | 空格组件 | 说明 | 样例（内容摘要） |
|--------|------|----------|------|------------------|
| `tabs=0, U+0020=0` | 866 | 无行首空格 | 顶格日志行，新条开始；带时间戳的 INFO/WARN 等 | `2025-12-31 06:38:57,103 INFO - FastModeR loading...` |
| `tabs=0, U+0020=3` | 134 | U+0020 × 3 | 续行；多为异常堆栈中的 `   at ...` | `at System.Reflection.RuntimeAssembly._nLoad(AssemblyName fil...` |

### 3.3 按状态列出（状态键 → 行数 + 一条样例）

```
tabs=0, U+0020=0  ->  866 行
  样例: 2025-12-31 06:38:57,103 INFO - FastModeR loading...

tabs=0, U+0020=3  ->  134 行
  样例: at System.Reflection.RuntimeAssembly._nLoad(AssemblyName fil...
```

### 3.4 空格组件与状态的对应（1000 行样本）

- **U+0020=0**：仅出现在状态 `tabs=0, U+0020=0`（顶格行）。
- **U+0020=3**：仅出现在状态 `tabs=0, U+0020=3`（3 空格续行）。

即：当前样本中“空格组件”只有一种类型（U+0020），两种数量（0 与 3），对应上述 2 种状态；未出现任何特殊空格（U+00A0、U+2003 等）。

---

## 四、分块规则小结

1. **新块**：行首无 TAB 且无空格（状态 `tabs=0, U+0020=0`）→ 新日志条开始。
2. **续行**：行首有空格无 TAB（如 `tabs=0, U+0020=3`）→ 归属上一条，同一逻辑块（如一条异常的多行堆栈）。
3. 若未来出现行首 TAB：TAB 数减少或为 0 时视为新块；TAB 数增加或不变且无“新时间戳行”则视为续行。
4. 若未来出现特殊空格：会以独立组件（如 `U+00A0`）出现在状态键中，分块时与 U+0020 一起看“总缩进”或按实现约定处理。

当前 `log_analyzer` 未按缩进分块，仅按行 `strip()` 后逐行解析；若需按块解析（如整段堆栈一条逻辑记录），可基于本规范用 `log_indent_spec.get_line_indent_state()` 判断新块/续行。
