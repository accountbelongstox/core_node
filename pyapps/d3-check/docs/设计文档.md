# D3-Check 设计文档（详细）

本文档为设计文档详细版，与 [DESIGN.md](DESIGN.md) 合并使用：DESIGN.md 为总览与索引，本文档侧重 Login Try 与 Battle.net 掉线重启的完整设计。

---

## 1. 概述

D3-Check 为暗黑 III / 暗黑 IV 自动化控制子应用，提供宏控制、日志监控、ROSBOT 扩展、Battle.net 掉线检测与重启等功能。

---

## 2. Login Try 与 Battle.net 掉线重启

### 2.1 触发条件

- **日志触发**：ROSBOT 日志文件（默认 `Documents\RoS-BoT\Logs\history.txt`）中出现配置的触发串。
- **配置项**：`log_detection.login_try`，默认 `"Login try"`。
- **常量**：未配置时使用 `config.constants.LOGIN_TRY_TRIGGER_DEFAULT`（`"Login try"`）。

### 2.2 流程（无 Python 线程）

当日志行包含触发串时，由 `d3utils.log_analyzer` 调用 `LoginTryScreenshotController.handle_login_try()`，顺序执行：

1. **读取配置**
   - Battle.net 可执行路径：`CONFIG["battlenet"]["battlenet_path"]`（如 `...\Battle.net.exe`）。
   - 若未配置或文件不存在，仅退化为全屏截图（`capture_screenshot()`），不进行掉线检测与重启。

2. **截取 Battle.net 窗口**
   - 使用 `d3utils.screenshot_provider.get_screenshot_provider().gen(use_optimized_capture=True, window_titles=BATTLE_NET_WINDOW_TITLES)`。
   - 窗口标题列表来自 `providor.providor_index.BATTLE_NET_WINDOW_TITLES`（多语言/多变体）。
   - 截图保存到 `config.constants.LOGIN_TRY_SCREENSHOT_DIR`，文件名前缀 `LOGIN_TRY_SCREENSHOT_PREFIX`（如 `login_try_battlenet_*.png`）。
   - 若未找到 Battle.net 窗口，退化为全屏截图后返回。

3. **OCR 判断是否掉线**
   - 使用 `providor.common_imports.CnOCREngine` 对上述截图做整图 OCR。
   - 掉线关键词：`config.constants.BATTLE_NET_DISCONNECT_KEYWORDS`，默认 `("Retry", "重试")`。
   - 若识别文本中包含任一关键词，判定为**掉线**。

4. **掉线时重启 Battle.net**
   - **结束进程**：`subprocess.run(["taskkill", "/F", "/IM", "Battle.net.exe"], ...)`，仅使用 Windows taskkill，不使用 Python 线程库。
   - **等待**：约 2 秒。
   - **启动**：`subprocess.run(["explorer", str(exe_path)], cwd=parent)`，exe 路径与工作目录来自配置中的 `battlenet_path`。

### 2.3 涉及模块与常量

| 模块/文件 | 职责 |
|-----------|------|
| `d3utils.log_monitor` | 按间隔读日志、调用 `log_analyzer.analyze_log_line(line)` |
| `d3utils.log_analyzer` | 解析每行日志；若包含 Login try 触发串则调用 `get_login_try_screenshot_controller().handle_login_try()` |
| `controller.login_try_screenshot_controller` | Battle.net 截图、OCR、掉线判断、taskkill + explorer 重启；可选全屏截图 |
| `config.constants` | Login Try 与 Battle.net 相关常量 |
| `providor.providor_index` | `CONFIG`、`BATTLE_NET_WINDOW_TITLES` |
| `d3utils.screenshot_provider` | 按窗口标题截取 Battle.net 窗口 |
| `providor.common_imports.CnOCREngine` | 截图 OCR，用于检测 Retry/重试 |

### 2.4 常量定义（config/constants.py）

- **LOGIN_TRY_SCREENSHOT_SUBDIR**：登录尝试截图子目录名（如 `login_try_screenshots`）。
- **LOGIN_TRY_SCREENSHOT_PREFIX**：截图文件名前缀（如 `login_try`）。
- **LOGIN_TRY_SCREENSHOT_DIR**：完整截图目录（`TMP_DIR / LOGIN_TRY_SCREENSHOT_SUBDIR`）。
- **LOGIN_TRY_TRIGGER_DEFAULT**：日志默认触发串（如 `"Login try"`）。
- **BATTLE_NET_DISCONNECT_KEYWORDS**：界面掉线关键词元组（如 `("Retry", "重试")`）。
- **BATTLE_NET_EXE_NAME**：进程名（如 `"Battle.net.exe"`），用于 taskkill。

---

## 3. LoginTryScreenshotController 接口

- **handle_login_try()**  
  上述完整流程：配置 → Battle.net 截图 → OCR → 若掉线则 taskkill + explorer 重启；异常或未配置时退化为全屏截图。

- **capture_screenshot()**  
  全屏截图并保存到 `LOGIN_TRY_SCREENSHOT_DIR`，返回保存路径信息。用于无 Battle.net 路径或未截到 Battle.net 窗口时的回退，以及仅需存档截图的场景。

- **get_login_try_screenshot_controller()**  
  返回全局单例，供 `log_analyzer` 等调用。

---

## 4. 日志与配置路径

- **日志目录**：由 `providor.providor_index.get_dynamic_paths()` 得到，如 `DOCUMENTS_PATH` + `paths.rosbot_logs_relative`（默认 `RoS-BoT/Logs`），即 `C:\Users\用户名\Documents\RoS-BoT\Logs`。
- **日志文件**：`paths.logs_file_relative`（默认 `RoS-BoT/Logs/history.txt`，检测 history.txt）。
- **Battle.net 路径**：`CONFIG["battlenet"]["battlenet_path"]`，UI 中在 ROSBOT 扩展面板配置。
