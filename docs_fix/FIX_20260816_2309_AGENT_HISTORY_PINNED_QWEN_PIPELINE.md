## Requirements (this round)

1. Pin agent-history article audio to Qwen3-TTS - no engine fallback.
2. Records must display the multi-sentence marker for EVERY record (the
   ChattTS-fallback record displayed nothing).
3. Records must display whether legacy audio was regenerated (and that the
   Laravel copy was replaced at the same time).
4. Multi-end update per specs; architectural, no patches; merge duplicates.

## Root cause of the ChattTS-sourced record

The `agent_history` priority profile was "configured default chain minus
cloud engines" -> qwen3tts first, chattts next. At 2026-08-16T12:32:41Z the
adopted legacy Qwen server was failing (`load_error`: paging file too small),
so the orchestrator fell back to ChattTS and published a long SINGLE-SHOT
article audio - degraded by the same class of problem (ChatTTS#113).

Two architectural layers close this:

- FIX_20260816_2210 (code identity) already guarantees the Qwen server runs
  current scripts (no more silently failing legacy listener);
- this fix removes the fallback itself for article audio.

## Design

### 1. Pinned profile (engine policy - single source of selection semantics)

`pycore/pyutils/tts/engine_policy.py`:

- `configured_tts_priority("agent_history")` now returns the single-engine
  order `("qwen3tts",)` (`_AGENT_HISTORY_PINNED_TTS`) - a one-element order is
  structurally fallback-free; a failed synthesis fails the pipeline item,
  which retries on a later tick instead of silently publishing degraded
  audio from the next engine.
- `_DEFAULT_AGENT_HISTORY_TTS` (derived local chain) deleted.
- `CLOUD_TTS_ENGINES` is now the single public definition; the audio stage's
  duplicated inline tuple was merged into an import of it
  (defense-in-depth guard kept: a pinned local pipeline must never publish
  cloud audio).

### 2. Marker-only rebuild rule (engine-agnostic)

`pycore/pyctl/agent_history/pipeline/audio_rebuild.py`:

- `_REBUILD_ENGINES` deleted. Candidate = `uploaded && rebuild_attempts <
  MAX && NOT tts_chunked` - the marker is the ONLY criterion ("missing data =
  legacy"), matching the record contract. Any pre-contract engine's audio
  (legacy qwen single-shot, the ChattTS fallback era) is regenerated through
  the SAME pinned stage and converges on multi-sentence qwen audio.
- Piggyback economics unchanged: 0 candidates -> straight to new work; after
  the backlog drains, each tick pays one local index scan (milliseconds).

### 3. Record provenance display (pycore UI)

`PcAgentHistoryRecords.tsx`:

- `tts_chunked` -> green `multiSentence` badge (every engine, not just qwen);
- uploaded without marker -> amber `legacyAudio` badge + rebuild hint
  (covers the ChattTS record from the report);
- `audio_rebuilt_at` -> sky `rebuilt` badge whose tooltip states the audio
  was regenerated by the pinned pipeline AND replaced on Laravel at the
  stamped time (rebuild is all-or-nothing: Laravel replace happens BEFORE
  the local stamp, so the badge always implies an updated Laravel copy).
- locales en/zh: `audioRebuilt` / `audioRebuiltHint` added (i18n, no
  hardcoded strings).

### 4. Laravel Main

No change this round: `submit` / `replace-audio` already persist
`tts_chunked` in article metadata (FIX_20260816_2242), and the deterministic
`<article_id>.mp3` replacement keeps the public URL stable.
