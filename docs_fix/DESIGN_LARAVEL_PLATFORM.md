# Laravel Platform

Scope: the `poly_apps/laravel_main` runtime, initialization, the pycore boundary and compute model, the AI gateway, machine data sync, pycore's selected-server authority, and the MCP Chrome service/cover tasks that Laravel drives.

Authority: code > config/*_contract.json > this document.

Binding spec: `development-guides/LARAVEL_GUIDE.md` (framework, paths, PostgreSQL, sub-app layout, UI). This document adds the designs behind those rules and does not repeat them. Authentication of every route: `DESIGN_AUTH_IDENTITY.md`.

## 1. Runtime

- Laravel 13 (`laravel/framework ^13.0`, PHP `^8.4`, `laravel/octane ^2.13`), headless API on port 9000 (`service_contract.json#ports.laravel_api_backend`).
- Octane server follows the web-server plane (`config/octane.php`: `WebServerPlane::FRANKENPHP` → `frankenphp`, else `swoole`). The FrankenPHP plane runs as systemd unit `ncore-laravel-frankenphp` (HTTPS/HTTP/3, 103 Early Hints, Mercure `service_contract.json#versions.mercure`).
- Timer: on FrankenPHP the scheduler (`schedule:work`) runs `OctaneTimerService::heartbeat` every second (`octane-timer-heartbeat`, `withoutOverlapping(1)`); slow `EXECUTION_BACKGROUND` tasks run in `octane-timer:background` every minute in their own process. Each heartbeat writes the heartbeat snapshot (`writeHeartbeatSnapshot`), so `schedule:run` never re-runs due tasks inline. On Swoole, `OctaneTimerServiceProvider` ticks inside Octane.
- Configuration comes from `app/Constants/LaravelConfig.php` through `config/*.php`; `.env` keys are never read (APP_ENV/APP_DEBUG/LOG_CHANNEL/SESSION/QUEUE/CACHE in `.env` are dead). Logs: size-capped daily files under `<laravel_db>/logs/`.
- Laravel 13 conventions in force: `PreventRequestForgery`; cache `serializable_classes=false` (caches hold arrays/scalars only); JSON session serialization; hyphenated cache/Redis/session prefixes in `LaravelConfig`; `casts()` methods; protected typed `#[Scope]` local scopes; `whereLike`; PostgreSQL-only JSON queries; `upsert` with non-empty unique keys; `Cache::flexible` for expensive dashboard metrics; poster claims with `FOR UPDATE SKIP LOCKED`.
- Version gate: Windows `scripts/start.ps1` → `upgrade_laravel_13.ps1`; Linux 175 → `scripts/shells/linux/debian/debian_com/laravel_upgrade_13.sh`. Laravel 13 continues; Laravel 12 asks `[y/N]` (anything but `y`, or non-interactive, stops; Laravel 12 never boots); after `y` only the verified `vendor` dir of the resolved Laravel root is removed (PowerShell rejects reparse points), `composer update --with-all-dependencies` runs, and the major is re-checked. Unsupported majors stop.
- Locale: `ApplyRequestLocale` maps `Accept-Language` to zh_CN/en; `bootstrap/app.php` pins `lang/`.
- Request-worker rules (2 vCPU / 3.7 GB server; a held worker is lost capacity): no request waits on pycore (no polling loop, no `app()->terminating` pipeline; long work answers 202 and runs in `octane-timer:background`); no request blocks on another request's cache fill (`LockedCache` serves last good or a degraded default); remote lookups cache failures as well as results (shorter TTL); hot-path queries are index-backed and totals use planner estimates (`TableRowEstimate`). Details: `DESIGN_QUEUE_PIPELINE.md` §11.

## 2. Initialization and schema

- `php artisan sys:init` (`InitializeApps`) is the only migration/initialization entry. It is orchestration-only (no direct DB/Schema calls); initializers and models own inspection and mutation. Required stages fail fast with `Command::FAILURE`.
- `migration:check-safety` runs before `migrate --force`. Schema changes are additive: create missing tables and add missing columns/indexes through `SafeMigrationHelper::alignTableStructureFromArray()`. Never `migrate:fresh/refresh`, drop, truncate, rebuild or recreate a table. `SafeMigrationHelper::addMissingColumns()` logs each added column, continues past a failing column, adds a NOT NULL column without default as nullable on a non-empty table (with a warning), and `findEquivalentIndex` prevents duplicate indexes. A status file such as `*_init_status.json` is not evidence that the schema was applied; reruns must converge to zero changes.
- Required stages: migrations, invite tables, user sync, TTS cache tables, voice-subtitle tables, TTS queue data sync (the intermediate queue is read into canonical tables without dropping it), TTS statistics, article libraries, dictionary init and summary, per-user QY tables, global tasks, media tables, punctuation markers, TTS configuration, and the in-place article type migration (rows updated in place; marker written only after success). TTS default engines/variants are read once and bulk-upserted; missing engine or variant configuration throws, with no synthetic in-code fallback.
- Reporting uses grouped aggregates (task statuses, one `UNION ALL` over language tables); worker statistics count `busy/online` only while the heartbeat is fresh.
- `sys:init` prints the admin invite code on every run. Seeding fills only missing defaults; it never overwrites operator-changed values.
- CodeMart seeded accounts: no hardcoded password. Contract `service_contract.json#codemart_admin_password`: secret file `<laravel_db>/.core_node_secrets/CODEMART_ADMIN_PASSWORD` (0600, not web-served), 24 chars base64url; `CodeMartV1DemoSeeder` reads it or generates and prints one; `php artisan codemart:admin-password --file <path>` applies it to every seeded account (idempotent). Demo seeding default is `LaravelConfig::CODEMART_SEED_DEMO`.
- Deploy ensure (175 Linux / Step175 Windows) is idempotent: repair or initialize only what is missing, never reset (an installed PostgreSQL is started, never reinstalled), regenerate the CodeMart password after a timed `[Y/n]` prompt (default Y, non-interactive Y), extract the book seed corpus to `<laravel_db>/seed_data/books/` (Laravel only reads it; it runs no tar/xz/7z/apt), and call `client_key_ensure_ready` before `sys:init`.
- AppQyV1 models inherit `AppQyV1Model` (connection, table map, canonical names, `createRecord`/`findById`, existence/count); dynamic language tables use `BindsAppQyV1LanguageTable` / `BindsAppQyV1DynamicLanguageTable`; media/poster queries compose as `Book/Subtitle → AppQyV1MediaSourceQueries → QueriesPosterMedia` (one ownership path; no model applies `QueriesPosterMedia` directly); shared study-source operations live in `AppQyV1StudySourceQueries`. No forwarding models, compatibility shims or Laravel 12 branches (`method_exists`/`class_exists` version bridges) exist.

## 3. pycore boundary and compute model

- Laravel never calls pycore; only pycore requests Laravel. Laravel never runs local models, TTS/STT, GPU or CPU-heavy tools. Such work becomes an available `global_tasks` row that a pycore pulls and completes.
- `App\Services\PycoreTasks\PycoreTaskQueue` is the one producer: `request()` is idempotent per `(task_type, group_key)` (group key = `client_task_id`, else body `client_task_id`/`Idempotency-Key`, else the input; a reused key with a different input → 409 `client_task_id_conflict`). Answers:
  - completed: the domain result;
  - queued: 202 with `pycore_task {status, task_id, task_type, client_task_id, required_compute, poll: /api/task/{id}/status, last_error?}`;
  - `pycore_unavailable`: the `errorWithCode` envelope plus Retry-After, `data = {task_type, required_compute, registered_pycores, eligible_pycores, last_seen_at, heartbeat_ttl_seconds, disposition: queued|rejected, task_id, client_task_id, retry_after_seconds}`; 202 when the task type's `offline_policy` queues, 503 when it rejects.
  - `availabilityView()` / `mayEnqueue()` apply the same rule to the existing lanes (queue-center heads, `/api/task` create, AppQyV1 task enqueue, `intelligentBatchQuery`); `poll($view, $watch)` is one non-blocking look at a pending task: completed, failed, unavailable, still pending (with the updated `{fingerprint, changed_at}` watch), or stalled after one heartbeat TTL without change. Nothing sleeps on a pycore task.
- `PycoreComputeRoster` schedules by the `compute_class` (`gpu | cpu_only`, plus `gpu_name`, `gpu_vram_mb`) each pycore reports on register and pull. Contract `task_types[].compute`: `gpu_required` (gpu only), `gpu_preferred` (cpu_only claims only while no fresh gpu pycore of that execution type has spare lease capacity), `cpu_ok`. A pycore whose in-flight count exceeds the least-loaded same-class peer by that peer's lease capacity gets nothing. Online = heartbeat within `task_contract.limits.worker_heartbeat_ttl_seconds` (120). Pull returns nothing when `mayClaim` is false; accept answers 409 when `canRun` is false. Workers without a compute class (browser workers) are never filtered. Availability is memoised 5 s per worker process.
- Unknown task types/queues answer 404 `LARAVEL_TASK_TYPE_UNSUPPORTED` with `{task_type, supported[]}`.
- Compute task types added for pycore (contract `task_contract.task_types[]`, validated by `QueueCenterContract::assertTaskTypeContract`, each with `compute` and `offline_policy`): `ocr_recognize` (cpu_ok, offline reject; `PycoreTasks\OcrRecognizeTask`, used by OCRController, McpV1OCRCtl, VoiceSubtitleProcessor) and `tts_synthesize` (cpu_ok, offline queue; `EdgeTTSService::generateAudio` on a cache miss, `TtsSynthesizeTaskProcessor` writes the file). Limits `worker_heartbeat_ttl_seconds` 120 and `pycore_unavailable_retry_seconds` 30. A pycore lists the execution types it serves in `processor_types`; the roster counts pycores per execution type.
- `client_task_id` (`PycoreTaskQueue::CLIENT_TASK_ID_RULE`, `^[A-Za-z0-9._:-]{1,128}$`) is accepted on the OCR and TTS generate routes, becomes the dedup group key and is copied into the payload; the payload's `input_sha1` detects a reused key with another input. Batch OCR answers a top-level `results[]` of per-item views. `POST /api/ocr/recognize` takes `{image_data (base64 or data URL) | image_path, model_type?, engine?, lang?, languages?, client_task_id?}` (`OcrRecognizeTask::decodeImageData`).
- Learning cards (`/api/app_qy_v1/learning/words`) carry `audio_task` (queued or unavailable view) while the word audio is pending pycore work; endpoints that only optionally pre-generate audio embed the same view.
- Voice subtitle (`VoiceSubtitleV1MainController::addToQueue`) records the task with its pipeline input (`payload.pipeline.input`, stripped from API answers) and answers 202 with `task_id`. `VoiceSubtitleV1PipelineTask` (background lane, 3 s) runs `VoiceSubtitleV1PipelineRunner`: each tick advances every live task one pass (20 tasks / 20 s budget). `VoiceSubtitleProcessor` checkpoints the extracted source text, the speech text and paragraphs, and the pycore tasks it waits on (`payload.pipeline.checkpoint`), so AI vision/rewrite/translation never repeat; TTS misses for all paragraphs are queued together, and a live pycore TTS/OCR task suspends the pass (`VoiceSubtitleV1PipelineSuspended`) until a later tick polls it. An unavailable/failed/stalled TTS or OCR step is reported `failed` with the view and throws; `VoiceSubtitleTaskManager::runPipeline` marks the task failed on any exception (`failTask` on the failed step). Task reads always come from the database (the runner writes from another process). Callers (laravel-manager `VoiceTab`, `VoiceSubtitleManager`) treat 202 + `task_id` as accepted (`McpV1API.vsAcceptedTaskId`) and follow the task through `GET /api/mcp/v1/voice-subtitle/tasks/{id}` (`vsFollowTask`, 3 s polls until a terminal status, 30 min cap) before reloading the queue.
- pycore → Laravel result and report routes answer the outbox contract: 200 accepted, 404 gone, 409/422 terminal, 5xx only on faults. Media ingest accepts only model_version 3 (chapter → slot tree).
- Video processing is always pycore work (`AppQyV1ProcessingCapabilityController` reports it); Laravel probes no ffmpeg/GPU. `SystemInfoService` caches tool-version probes 24 h per tool (`system_info:tool_version:<tool>`).
- Light local work stays in Laravel, capped by `App\Support\ResourceLimiter` at 5% CPU and 5% memory per job: spawned tools run in a transient systemd scope (`CPUQuota` = 5% × cores, `MemoryMax` = 5% RAM; fallback prlimit + nice/ionice + cpulimit); in-process GD refuses a bitmap above the memory share before decoding. Interpretation of the user's 5% rule: it keeps background light work from hogging the box. A synchronous tool run inside an HTTP request (a user waits and a request worker is held) therefore runs without the CPU quota (no nice/ionice/cpulimit) but keeps the memory cap and a stall guard (`timeout`, 300 s, kill after 5 s); console processes (timer lanes, artisan) keep the full 5% CPU quota. Windows has no PHP-reachable cap, so endpoints that spawn tools answer 501 `platform_unsupported` there and are marked `platforms: [linux]` (ItTools PDF, 7z/tar media archive extraction).
- `App\Support\ApiComputeCatalog::classify()` is merged into every `/api_info` endpoint: `pycore_required`, `compute` (`none | light | pycore`), `pycore_task_types`, `direct_api_capable` / `direct_api_kinds` (marker only, read from `queue_center_contract.json` task types via `QueueCenterContract::taskTypeDirectApi()`; true for OCR, TTS lanes and STT types), `auth`, and `platforms` when linux-only. Everything unmatched is `none`.

## 4. AI gateway

- Keyed remote AI (chat, translation, vision, image) runs in Laravel through `App\Services\AiGateway`: `AiGateway::chatWith/generateText/describeImage/generateImage`. No provider HTTP call exists outside that namespace. Only work no available key can serve becomes a pycore task.
- `AiProviderRegistry` is the single provider catalog (identity, `key_base`, models, free models, limits, tier, client, base URL, capabilities) and the laravel/ai SDK view (`SDK_DEFAULTS`, `SDK_PROVIDERS`, `sdkConfig()` = `config/ai.php`). Keys are read from `.secret_keys/.secret_ignore/<KEY>` (`AiSecretLoader`, indexed `_1.._5` then bare), the same files pycore reads; `AiKeyRotation` adds failover, not budget. Dispatch order: free → balance → paid.
- OpenRouter is free-only: `OpenRouterFreeOnly::isFreeModel` (`:free` suffix, zero prompt and completion price, or `openrouter/free`) gates catalog, chat (`AiChat`, `AiSdkChat`, the ≤3-model in-request fallback) and image (a free image model from the cached catalog, else `AI_FREE_IMAGE_MODEL_UNAVAILABLE`). Paid ids are refused with `AI_PAID_MODEL_REFUSED` before any key or budget is used. `hasImageProvider()` counts OpenRouter only while the stored catalog offers a free image model.
- Free catalog cache (per modality, `openrouter_free_catalog:v2:*`): every fetch result is stored, a non-empty one for 1 h, a failed or empty one for `services.openrouter.catalog_failure_cache_seconds` (600 s; a failure keeps the last good catalog); past expiry one caller refetches under a single-flight lock while others serve the stored entry. Request paths (`hasImageProvider`, `candidates('image')`, the OpenRouter image call, the translation model list) read the cache only (`cachedFreeCatalog`, `freeImageModel(true)`); `OpenRouterCatalogWarmTask` (background lane, 300 s, while OpenRouter is configured) refreshes it; `AiProbe` fetches on an explicit probe. With nothing stored the text catalog is the registry free ids and the image catalog is empty.
- `AiChat::chatOnce` key rotation shares one call budget (the caller's timeout, default 90 s): each attempt gets what is left, and an exhausted budget ends the rotation (`ai_gateway.rotation_budget_exhausted`).
- In the SDK view, `openrouter` and `openrouter-free` offer only the `text` capability through the free router (`OpenRouterFreeOnly::FREE_ROUTER`); OpenRouter images go through `AiGateway::generateImage` with a free catalog image model, and the SDK view offers no OpenRouter images, audio, transcription, embeddings or paid default.
- Base-URL override secrets (`url_key` / `base_url_key`, e.g. `OPENROUTER_BASE_URL_n`) apply only when the value is an http(s) URL (`AiProviderRegistry::secretUrlOr`, used by `sdkConfig()` and `baseUrl()`); any other value falls back to the registry base URL and is never sent as a URL. This code runs while `config/ai.php` is evaluated (before facades exist), so it never logs.
- Callers that need provider-specific sampling or long replies pass them as data: `AiGateway::chatWith(..., $timeout, $sampling)` with `AiGateway::directSampling($provider)` (registry `direct_sampling`, OpenRouter `{temperature: 1.0, top_p: 1.0}`, never max_tokens) and `DIRECT_CLIENT_TIMEOUT_SECONDS` (300; TranslationService, SentenceEnrichmentService, VoiceSubtitleProcessor vision/rewrite). Gateway defaults: `OpenAiCompatClient::DEFAULT_SAMPLING` (temperature 0.7, max_tokens 2048), 15 s connect timeout. Provider status: `AiGateway::providersStatus()`.
- `AiRateLimiter` enforces per-provider rpm/rpd on the store shared with pycore, `<core_node>/.ai_state/ai_rate_usage.json` (flock + atomic rename; calendar buckets keyed and reset in UTC, identical to pycore). OpenRouter: 20 rpm, 1000/day shared by both runtimes. It counts requests per provider (no token or per-key windows, which would desynchronise the two runtimes); extra keys add failover only.
- Google translation is the keyless `GoogleTranslateClient` (primary translate.googleapis.com, fallback clients5 dict-chrome-ex; 30-day cache).

## 5. Machine data sync

UI: laravel-manager → Database Manager → Machine Data Synchronization (`DataSyncTab.tsx`, `DataSyncModel.ts`). Backend: `app/Services/DataSync/*`, `DataSyncController`, `routes/DashboardRouter/DatabaseManager.php`, driven by the Octane timer. Contract: `service_contract.json#data_sync` (protocol 5; roles source/fetcher drive, receiver/exporter are passive, receiver/fetcher write; `terminal_retention` 5). Peer routes: `DESIGN_AUTH_IDENTITY.md` §1.

- Modes: push (source → receiver) and pull (fetcher ← exporter) for a node the peer cannot reach. Operator routes (`dashboard.auth`): `GET|POST dashboard/db-manager/sync`, `sync/probe`, `sync/fetch`, `GET sync/{id}`, `sync/{id}/target|pause|resume|cancel`. Each start chooses databases, resources and optional compression.
- The target address is optional at start: the driver collects the local database/resource manifest, then waits at the address-binding step; `POST sync/{id}/target` binds the address to the same session (same id, options, progress and checkpoints). The manifest is refreshed once after binding to snapshot current schema and files.
- Step lists come from `DataSyncStepCatalog` (`SOURCE_STEPS`, `FETCHER_STEPS`, `EXPORTER_STEPS`, `RECEIVER_STEPS`); UI progress is backend-owned, so page reloads, browser disconnects, endpoint reconnects and backend restarts restore the same step list on both nodes. Receiver/exporter sessions are visible but controlled by their driver.
- The UI starts, pauses, resumes, cancels and observes; the Octane timer executes. Pause changes persistent state without discarding row/byte checkpoints. Per-session OS file locks (`DataSyncSessionLock`) serialize timer advancement, pause/resume and receiver writes and are released by the OS when a worker exits.
- Resource roots (`ResourceSyncService::roots()`): `static`, `avatars`, `uploads`, `tts_data`, `app_external_data`, `app_qy_v1_word_audio`, `app_qy_v1_sentence_audio`, `app_qy_v1_word_images`; aliases resolving to an already covered path are transferred once. Files compare by relative path, size and SHA-256; default transfer is uncompressed resumable fixed-size file chunks (a repeated chunk reconciles to the receiver's byte offset; a file already present with the expected hash returns completed at once); optional mode archives the difference list with system 7-Zip and transfers the archive in resumable chunks, the receiver validating archive hash and entry paths before extraction. Row chunks are capped by row count and encoded bytes.
- One active session per node; starting a driver cancels every other active local session; terminal sessions are never reused. Topology changes are serialized by `DataSyncTopologyGuard`; a node that is receiving cannot start a driver.
- Cancel propagates end to end (`POST sync-peer/sessions/{id}/cancel`, `export-sessions/{id}/cancel`); status `cancelled`. Passive sessions end after `PASSIVE_IDLE_SECONDS` (3600) of driver silence; a new prepare supersedes a passive session idle longer than `PASSIVE_SUPERSEDE_SECONDS` (180). Paused drivers send keepalive every `KEEPALIVE_SECONDS` (60).
- Passive work runs in the passive node's own ticks: inventories and manifests are built there, stored as session artifacts (`DataSyncArtifactStore`), and peer requests only read artifacts or chunks. Session JSON stays small; artifacts, parts, archives and receipts are removed at session end. State writes stage a pending copy before replacing the primary JSON; UI polling reads lightweight summaries (aggregate counts only, no paths, manifests or tokens).
- Inventory is O(tables) via bulk PostgreSQL catalog queries; resource manifests are incremental via a per-root hash cache keyed by (path, size, mtime).
- Address normalization: bare host/IP → `http` + port 9000; explicit scheme without port → scheme default (https 443, http 80); explicit port kept.
- Schema compatibility is per table: missing or different tables are skipped and recorded in `database_results.skipped`; verification covers synchronized tables only.
- Idempotency: rows merge additively by primary key, else first unique index, else exact-row existence (rows only on the writer are never deleted); binary cells use a base64 envelope; JSON/JSONB canonicalized before verification; tables ordered by foreign keys; connections deduplicated by physical signature; PostgreSQL sequences advanced. The receiver takes a `pg_dump` backup of each selected database before it becomes ready. Files are committed only after SHA-256 matches; same-hash files are skipped. Optional system 7-Zip batches go through `SystemArchiveManager`. HTTP 502/503/504 and connection failures are retryable.
- Never test a remote peer through loopback or LAN addresses; the remote test peer is `api.si.12gm.com`, and its `/sync-peer/health` protocol version shows whether it runs the new code. Acceptance: pull `api.si.12gm.com` → local twice; the second run reports only unchanged rows and no transferred files.

## 6. Selected server authority (pycore side)

pycore works for exactly one selected Laravel server; the unit of selection is a server (`server:<server_id>`), URLs are routes to it.

- One authority: `pycore/pyutils/laravel/endpoint_manager.py` (`selected_namespace`, `selected_server_matcher()`, `serves_selected()`, `task_namespace`, `work_endpoint_error()`); a route of unknown identity is not the selected server. Every selection notifies listeners at once; the background probe only adopts the resolve winner.
- Admission (`pyutils/tts/audio_queue_center.py`): each task is bound to `_laravel_server_url` (`bind_task_server`); only selected-server tasks are accepted, restored and popped (others settle as `laravel_server_not_selected`); a switch runs `retain_selected_server()`.
- Workers always follow the active route and re-register on change; they refuse a claim for another server.
- Outbox drains only the selected server; rows of other servers are parked (`stats.by_namespace[].parked`) until it is selected again. A row whose URL is down uses another live route of the same server.
- Entry points (`ui/queue_center/accept_task`, word full pull, orchestration login) reject `LARAVEL_ENDPOINT_UNKNOWN` / `LARAVEL_SERVER_NOT_SELECTED`.
- One catalog: `pyfoundations/service_contract.py::laravel_api_catalog_urls()`. Panel API: `ui/assist/laravel_endpoints` (relay `general_read`), `ui/assist/laravel_endpoints_probe` (relay denied); selection stays `ui/assist/bind_laravel_endpoint`. The browser's own transport selection stays separate; the panel warns when it differs.

## 7. MCP Chrome service and library cover tasks

Contract: `service_contract.json#mcp_chrome` (native host, build dirs, build stamp, service name/limits, Windows task name, extension ids).

- Background service (optional, idempotent): `apps/mcp-chrome/scripts/start.sh` / `start.ps1` ask once before building, default N (`MCP_CHROME_AS_SERVICE=yes|no`, `--service`/`--no-service`/`--uninstall-service`, `-Service`/`-NoService`/`-UninstallService`; unattended takes the default). Installed → converge without prompting. Linux: unit `ncore-mcp-chrome` as the desktop user with session env baked in, boot start, CPU 200% / 4G (`converge_systemd_service`, `systemd_desktop_session_env`). Windows: per-user at-logon task `ncore-mcp-chrome` (`StartupManager.ps1`), action `start.ps1 -ServiceRun`. A foreground build pauses the service and converges it afterwards.
- Hot reload: `scripts/dev-watch.mjs` (`bun run dev`, both OSes) runs tsup watch, nodemon and WXT dev; the native host exits when its own `dist/index.js` changes and the extension reconnects; production builds write `build-stamp.json`, polled by `entrypoints/background/build-reload.ts`. The supervisor only wakes Chrome when disconnected.
- Global API: default endpoint `production` from `service_contract.json#access`; `api_settings` is the only persisted API location; the background re-points running workers on change; one resolver `getApiBase()`.
- Shared helpers only: bash `prompt_read_default` (`prompt_common.sh`), `converge_systemd_service` + `systemd_desktop_session_env` (`systemd_service_manager.sh`, also used by `pycore_service.sh`); PowerShell `Read-YesNoDefaultNo` (`NssmServiceManager.ps1`) and `Register-/Test-/Stop-/Unregister-UserLogonTask` (`StartupManager.ps1`). The service needs the desktop user and session (it drives the user's Chrome), so root/LocalSystem wrappers are not used.
- Bottom-layer rules: native host name, port and build dirs defined once (contract); one Laravel HTTP path per concern (task detail through the worker client; endpoint selection in the `useEndpointSelection` composable shared by `ApiSettings.vue` and `EndpointDropdown.vue`); worker-id key, heartbeat default and scheduling hooks defined once in `SimpleWorkerRuntimeBase`.
- Build output: `apps/mcp-chrome/build_output/build_extension` (Firefox `build_extension_firefox`), git-ignored.
- Library covers (`queue_center_contract.json#library_cover`: `library_cover` generate on `remote_gemini`/image, `library_cover_search` on `remote_poster`/poster, `fallback_grace_seconds` 20, `fallback_worker_id` `laravel-ai`):
  - `POST /api/app_qy_v1/vocabulary/libraries/cover/tasks` `{ids[1..200], mode: generate|search, prompt?}` → `{tasks, skipped}`; `GET …/cover/tasks?ids=` → flat cover fields plus `task`. Enqueue is idempotent per library (`group_key = library_cover:{id}`); list rows carry `cover_task` and cover URLs versioned `?v=<cover_last_generated_at>`.
  - Chrome `gemini-image` pulls `library_cover` on Mercure wake; `media-image` pulls `library_cover_search`; results go through the typed result route to `LibraryCoverTaskProcessor` → `submitCover(force: true)`.
  - `AppQyV1LibraryCoverFallbackTask` (5 s, one task per tick): a cover task unclaimed past the grace window (or with no online worker for its lane) is completed by Laravel AI when `AiGateway::hasImageProvider()`. `ai-regenerate` answers 409 while a live task exists. Reads never reset `failed`.
  - UIs (laravel-manager libraries/vocabulary/db-manager, pycore-manager, wordnew) share `LibraryCoverTaskModel`; all strings via i18n.

## 8. Verification

- `php -l` on changed files; `php artisan route:list` (middleware columns show `client.key*`/`dashboard.auth`).
- `php artisan sys:init` twice: the second run adds nothing.
- `php artisan tinker --execute='echo App\Support\QueueCenterContract::taskTypeExecution("tts_synthesize");'` → `remote_compute`.
- With every pycore stopped: `POST /api/ocr/recognize` → 503 and TTS generate → 202, both `pycore_unavailable` with Retry-After.
- After changing `config/*_contract.json` on a server: restart the Octane/FrankenPHP workers (contracts are cached per worker) and `php artisan optimize:clear` if caches are used.
