# CodeMart Server Functional Status

Updated: 2026-09-18 (functional-only revision)
Main design: `DESIGN_20260823_CODEMART_PYCORE_UI_LARAVEL_MAIN.md`

This record describes only which business functions the CodeMart server
provides and their status. It contains no code, file, or architecture
descriptions; the implementation is the authority for those.

## Identity and onboarding

- Shared account login and CodeMart registration with requested role
  (client or developer). Status: done.
- Registration with the installation super code (generated by the
  deployment script) elevates the new account to platform administrator.
  Status: done.
- A successful registration returns a ready-to-use session. Status: done.
- Onboarding truth (completed and next steps, contact verification,
  identity verification, deposit requirement) is computed by the server
  and returned to the interface. Status: done.

## Bootstrap projection

- One bootstrap projection exposes the account, CodeMart roles,
  capabilities, canonical state vocabulary, deposit and commission policy,
  and onboarding status. Interface visibility follows these capabilities.
  Status: done.

## Roles and capabilities

- Multiple CodeMart roles per account; role membership is separate from
  platform administrator rights. Status: done.
- Client role activates at registration; developer activation requires
  verification, profile, and the configured deposit policy. Status: done.

## Projects, tasks, and marketplace

- Client project creation, editing, and publication with canonical project
  states (draft, proposal review, funding pending, open, in progress,
  paused, completed, archived, cancelled). Status: done.
- AI requirement analysis with proposal review, accept, and revision
  request; accepting a proposal moves the project to funding pending.
  Status: done.
- Milestones and task publication. Status: done.
- Marketplace browsing and atomic task acceptance (only one developer can
  claim an open task). Status: done.
- Developer submissions with pending review, approved, needs revision, and
  rejected states. Status: done.
- Reviewer queue and review decisions. Status: done.

## Money and trust

- Wallet summary, transaction history, deposit status, project funding,
  escrow visibility, and refund requests. Status: done.
- Deposit policy per role is server configuration shown read-only.
  Status: done.
- Ledger entries are immutable; corrections are compensating entries.
  Status: done.
- All finance mutations and task acceptance are idempotent: repeated
  requests with the same idempotency key return the prior result.
  Status: done.
- Identity documents are private and authorized, never public paths.
  Status: done.

## Notifications

- Domain notifications (finance, role, project events) with read state.
  Status: done.

## Public surface support

- Public home projection with live aggregate counters and approved
  testimonials. Status: done.
- Server-calculated project estimate (budget, duration, effort, team)
  driven by server policy. Status: done.

## Administration functions

- Platform overview totals and pending-work counters. Status: done.
- User search and CodeMart role status management (activate, suspend).
  Status: done.
- KYC submission review with approve/reject. Status: done.
- Deposit listing and payment confirmation that activates the related
  role; confirmation is idempotent. Status: done.
- Refund request visibility. Status: done.
- Cross-user project listing and state visibility. Status: done.

## Data safety

- Initialization is idempotent and integrated into the system init flow;
  existing tables are modified in place and never dropped or recreated.
  Status: done.
- No existing CodeMart data or Flutter reference source is deleted.
  Status: done.
