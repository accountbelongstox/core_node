# Agent History: Prompt Sources, Realtime Monitor, Derive/Rewrite, Notifications, Article Delivery

Scope: local AI-agent prompt extraction (pycore `pyctl/agent_history`), the realtime prompt monitor, prompt transforms (derive/rewrite), tray/desktop notifications, the pycore-manager `/pycore-manager/agent-history` page, and the Laravel article submit that receives generated articles.

Authority: code > `config/pycore_rpc_contract.json`, `config/pycore_relay_contract.json`, `config/agent_history.settings.json` > this document. UI shell rules: `DESIGN_UI.md`. Relay: `DESIGN_RELAY.md`.

## 1. Tools and scan center

- Tools (12, one table): `pyfoundations/agent_paths.AGENT_HISTORY_OFFICIAL_HOME_MARKERS` — `agent`, `pi`, `claude`, `codex`, `cursor`, `gemini`, `kimi`, `antigravity`, `cline`, `vscode`, `windsurf`, `trae`. Per tool: official env override (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GEMINI_CLI_HOME`, `KIMI_CODE_HOME`), default dirs, `platforms` (`win32`, `linux`), and the `verified` on-disk format version. Key order = UI display order; pipeline `SUPPORTED_TOOLS` derives from it. No second tool list anywhere (UI reads the supported set from `ui/agent_history/runtime_get`).
- Users-roots (`agent_paths`): OS roots `C:/Users` (Windows), `/home` + `/root` (Linux); launcher slot roots from `AGENT_LAUNCHER_SLOT_PROFILES` (every `scripts/winenvs/*.ps1` / `scripts/linuxenvs/*.sh` launcher → tool, root key, slot) via `AGENT_SLOT_ROOT_TEMPLATES` (`programing` = `<data>/Users` / Windows programing users dir, `tmp`, `kimi_fallback` `~/.kimi_slots`, `openai_tmp` `/tmp/Users`). `AGENT_SLOT_USERS_ROOTS` is derived from the profiles. Launchers that keep the real home (claude1-5, claudeteam, claude<vendor>, codexyolo, kimiyolo, agyyolo, ssh*) are covered by the OS roots. Env `PYCORE_AGENT_HISTORY_USERS_ROOTS` (os.pathsep) extends the roots.
- `pyfoundations/agent_home_scanner.py`: `scan_user_homes()` = process home + one level under each users-root; a root carrying an agent marker is itself a home; homes deduped by `(st_dev, st_ino)` (bind mounts) and realpath (junctions); `is_human_account()` excludes `AGENT_HISTORY_NON_HUMAN_USERS` / `_SUFFIXES` and applies the passwd rule (uid 0, or uid ≥ `AGENT_HISTORY_HUMAN_UID_MIN` with a login shell). `unreadable_user_homes()` is reported in status, runtime and a startup warning.
- Root read helper (Linux): `pyservice_entry.sh` starts `pyctl/agent_history/root_spool_main` as root before dropping the worker to the desktop user; it exits with the worker. Every `AGENT_HISTORY_ROOT_SPOOL_INTERVAL_S` it parses only regular files the worker cannot read that stay inside their home (realpath containment, `st_nlink == 1`) and writes parsed sessions to `AGENT_HISTORY_ROOT_SPOOL_DIR` (`root:<worker gid>`, 0750/0640, atomic, `O_NOFOLLOW`, flock single instance). The worker overlays the spool on discovery and live-scan descriptors and never gains privileges; covered homes leave `unreadable_homes`; `root_spool` status is in `status` and `runtime_get`.

## 2. Prompt sources (`pyctl/agent_history/sources/`)

- `source_kit`: shared readers, timestamp/content normalisation, injected-prefix filter (`AGENT_HISTORY_INJECTED_PROMPT_PREFIXES`), `SessionDraft` (the one session accumulator: first/last ts, models, turn cap, record shape).
- `source_specs`: `SourceSpec`/`ToolSpec`, the one discovery implementation (globs or non-following walk, realpath root dedupe, size cap, directory sources, fallback scope `home`/`root`), `editor_user_dirs()`.
- `tool_specs.TOOL_SPECS`: the only per-tool table (roots, patterns, format, format options, Pi root resolver). `EDITOR_APPS` declares VS Code-family editors (VS Code/Insiders/VSCodium, Cursor, Windsurf, Trae incl. CN, Antigravity); `editor_chat_sources()` yields their KV-store and `chatSessions` sources. Cline tasks are found in every editor's globalStorage.
- `source_registry.source_registry`: the one registry; validates specs against the markers; `tools`, `has_tool`, `discover`, `discover_all`, `parse`. Used by the service and the root helper.
- Formats are named by data shape (no product names), `sources/formats/`: JSONL `content_block_log`, `response_item_log`, `wire_event_log`, `typed_entry_log`, `typed_history`, `block_transcript`; JSON `message_list`, `project_temp_json`, `chat_session_file`, `markdown_artifacts`; SQLite `prompt_store_sqlite`; shared `chat_conversations.ChatLayout`.
- Read-only prompt store: `prompt_store_sqlite.SqlitePromptStore` (instance `sqlite_prompt_store`) reads `state.vscdb` key-value tables read-only via `database/adapters/sqlite_readonly.query_rows`. A `KvStoreLayout` lists `KvTable`s (name, LIKE key filters, optional referenced-row key template; missing tables skipped) and a `ChatLayout`. Referenced message rows resolve with one prefix query per conversation. Caps: workspace DB 50 MB, global DB 512 MB. Cursor reads the KV store only when no agent transcripts exist. `chat_session_file` reads `chatSessions/*.json[l]` (VS Code mutation log kinds 0-3).
- Prompt semantics (human input only): Kimi counts only `origin.kind == user` (`system_trigger`, `task`, `injection` and subagent wires are turns, not prompts); Claude adds `queued_command` attachments, honours `isMeta`/`origin.kind`, skips sidechain prompts, dedupes the same prompt recorded both ways; Codex marks injected user text `system`; the injected-prefix filter applies to every format.
- Notable layouts: Kimi `sessions/<wd>/<id>/agents/{main,agent-*}/wire.jsonl` + `user-history/<md5(workdir)>.jsonl` (both `.kimi-code` and `.kimi`); Codex `sessions/**/rollout-*.jsonl`, `archived_sessions`, `history.jsonl`; Claude `projects/<slug>/*.jsonl` + `history.jsonl`; Gemini `tmp/<project>/{logs.json,chats/session-*.json[l],checkpoints}`; Cursor `projects/<slug>/agent-transcripts/**/*.jsonl` (one user entry = one prompt, assistant text until the next user entry = one reply; tool events are turns only); `agent` covers `.agent/**` and OpenClaw `.openclaw/agents/<agent>/sessions/*.jsonl`. No synthetic project values.
- Prompt ids are content-stable: `session#sha1(ts|text)[:12]` (`-n` suffix for duplicates).
- `EXTRACTOR_SCHEMA_REVISION` (`agent_history_service.py`) bump forces one baseline re-parse that emits no prompt-new events. Persisted source records carry `source`/`format`.

## 3. Extraction, store and caches

- Service split: `agent_history_service` (extract pass, live scan), `source_scan` (homes, spool overlay, descriptors `mtime:bytes`, signature), `prompt_events` (prompt-new choke point), `extract_probe` (`ui/agent_history/test_extract`, read-only per-tool probe), `agent_history_index` (SQLite extract store `<agent_history store>/agent_history.sqlite3`: sessions, flat prompt list with an FTS5 trigram search index, per-source state, meta signature/schema revision/counts/`revision`; repository `database/repositories/agent_history_store_repository.py`, schema `database/schema/agent_history_store_schema.py`, TableKeys `AGENT_HISTORY_{SESSIONS,PROMPTS,SOURCES,STORE_META}`; one-time import of the pre-SQLite `index.txt`/`prompts.txt`/`state.txt`, meta `txt_imported`), `agent_history_txt` + `txt_format` (`sessions/*.txt` transcripts, `prompt_edits.txt`).
- Extraction is always on, independent of article processing and tool selection. Signature short-circuit, per-source incremental reparse, stable `source_id`, `ended_ts` per session. One pass is one SQLite transaction that replaces only the changed sessions' rows, prompts and source records.
- New prompts = ids never seen in the store (checked against the prompt table before the pass commits), deduped within a run. A prompt is emitted exactly once.
- Caches: `snapshot_cache.VersionedSnapshotCache` (bounded version/TTL base, per-key generations with leases, stale-while-refresh, strict mode for revision-bearing ID pages; `StatusSnapshotCache` subclass). The session catalog and tool source revisions are keyed by the store `revision` (THREAD_BUS signal, no owner hop); prompt lists and ID pages are SQL queries; session events keyed by file `mtime_ns:size`; tool-card statistics keyed by per-tool source revision + processing cursors; `ui/agent_history/status` is one shared snapshot per tool set (1 s) and home/root-spool coverage is refreshed at most every 30 s; OpenRouter dashboard keyed by UTC day + usage-file `mtime:size`. Live values (operation, phase, tick state, rate status, config) are read on every exchange.
- Read surface: DIFF ID pages + lazy materialization — `session_id_pages`/`session_page`, `prompt_id_pages`/`prompt_page`, `article_record_id_pages`/`article_record_page`, `tool_fragment_id_pages`/`tool_fragment_page` (kinds prompts/replies/processed/pending). Every ID-page request sends its cached revision; a match returns `unchanged` before any read.
- `prompt_records` (`pyctl/agent_history/prompt_records.py`): one SQLite store `<agent_history store>/prompt_records.sqlite3` on its own serialized owner thread, repository `database/repositories/prompt_record_repository.py`, schema `database/schema/prompt_record_schema.py`, WAL, TableKeys `AGENT_HISTORY_PROMPT_{FEED,ARCHIVE,META}`, namespace `util_agent_history`, file mode 0640. Feeds: `new` (≤ `NEW_FEED_MAX_PER_TOOL` 2000 per tool by ts), `derived`, `rewritten` (≤ `TRANSFORM_FEED_MAX_ITEMS` 1000 by write recency), text cap 4000; `archive` is append-only, never trimmed, key sha1(tool|os_user|ts|text), every prompt of every extract pass. Write-only mirror: extraction never reads it. A one-time import of the earlier JSON/JSONL record files runs at first open (meta `legacy_imported`).

## 4. Realtime monitor and refresh

- Heartbeat lanes (`tick_service.py`, `heartbeat.py`): `agent_history_extraction` (all tools, `PYCORE_AGENT_HISTORY_EXTRACT_INTERVAL`, default `PYCORE_AGENT_HISTORY_INTERVAL` 10 s), `agent_history_pipeline`, `agent_history_upload`, `agent_history_live_monitor`.
- Monitor switch = persisted config `live_prompt_monitor` (default true) + UI presence lease `agent_history.live_monitor` (lease = 3 × poll interval). The UI holds the lease over the pycore event socket (`useAgentHistoryPromptFeed` → `holdPycoreLease(PYCORE_PRESENCE_LEASES.agentHistoryLiveMonitor)`) while the switch is on; the page toggle writes `live_prompt_monitor` through `persistAgentHistoryArticleConfig`. The `agent_history_live_monitor` lane scans the enabled tools while switch ON and lease present; no UI → no lane.
- `ui/agent_history/live_scan` `{tools?, enabled?, release?}`: `enabled` persists the switch, `release` ends presence, otherwise renews the lease and scans (server throttle `PYCORE_AGENT_HISTORY_LIVE_SCAN_INTERVAL`, default 5 s, `{throttled, retry_after}`); `last` carries `scan_seq` so a client never re-applies an old result. `monitor` snapshot `{enabled, tools, present, active, lease_remaining, interval, poll_interval, scan_seq}` is in every response and in the status snapshot.
- Live scan: tools ∩ registry; per-tool descriptor map seeded from persisted `state["sources"]`; unchanged tool = skipped without opening files; descriptors committed only after a successful extract; `changed` only when sources changed and extract succeeded; errors surface as `error`.
- All extracts and live scans serialize on one lane (`_ExtractGate`, `_extract_busy`); a tick skipped while the lane is busy sets `_extract_pending` and runs before release (no starvation).
- Tick boundary: `_run_extract`, `_run_pipeline`, `_run_upload` and `_run_live_scan` are thread/bus job boundaries; each catches, ColorPrints the lane context and keeps the loop alive (snapshot still published); `_run_live_scan` returns `{error}`.
- `ui/agent_history/refresh` ("Refresh now"): force-extract all tools + `invalidate_agent_history_caches()` (snapshot and status caches, prefix `agent_history.`), returns `{queued, cache_invalidated}`; never a device refresh. The UI reloads pages bypassing `sinceRevision` and bumps tool statistics.
- Config binding: `BusSignals.AGENT_HISTORY_CONFIG_CHANGED` fires on any user-facing key change; UI runtime store applies the pushed config; a mutation sequence guard drops snapshots requested before the latest save; the tray menu refreshes from the same event. `min_raw_words` is clamped by the backend.

## 5. Prompt-new event and transports

- `prompt_events.emit_prompt_new` is the single choke point: newest first, `PROMPT_NEW_EVENT_CAP` 20; per prompt one `ColorPrint.green` line `[AgentHistory] New prompt detected agent=<tool> user=<os_user> prompt="<first 10>...<last 10>"` (full text when ≤ 20 chars, whitespace collapsed); then THREAD_BUS `agent_history.prompt.new` `{generated_at, tools, prompt_count, prompts[{id, tool, os_user, session_id, ts, time, text≤200}]}`; then `prompt_records.append_new`.
- Direct UI: pycore `/api/ws` event socket → `pycoreEventBus` topic `agentHistoryPromptNew`. Relay UI: `laravel_relay_agent_service` posts device events `agent_history_prompt_new`, `agent_history_prompt_derived`, `agent_history_config_changed` (relay contract, payload `[pairing_id, device_id, revision, metadata]`) → Laravel outbox → Mercure → `PYCORE_RELAY_DEDICATED_TOPICS` replays them on the same bus topics. UI code is transport-agnostic. Every other public topic (including `agent_history.prompt.rewritten`) reaches relay devices through the batched `pycore.events` tunnel (`DESIGN_RELAY.md`).

- Preset prompts (`pipeline/prompt_templates.py`, config keys `prompt_article_cn`, `prompt_translate_en`, `prompt_derive_en`, `prompt_rewrite_en`): user config non-empty wins, code default is the fallback; edited on `/pycore-manager/ai?tab=capability` (`PcAiProviderPromptsEditor`). ## 9. Article pipeline (pycore)

- Planner: per-tool backfill cursor, live cursor and backfill boundary; cursors are never reset; live batches preempt backfill across tools; backlog round-robin after `last_tool`; newest first. Item key includes tool + fragment id.
- Stages: CN article + EN translation via `ai_free_text` (two OpenRouter requests per article), audio through `pipeline/audio_stage.advance_audio_synthesis` -> `pyutils/tts/queued_synthesis.queued_tts_synthesis`: one non-blocking, idempotent qwen3tts queue job per article (`client_job_id = qwen3tts-<sha256(job scope, text, language)>`, job state kept on the operation item, short polls, managed-service hold while the job runs; text above `job_text_max_chars` fails). The profile `agent_history` is pinned to `("qwen3tts",)` (`pyutils/tts/engine_policy._AGENT_HISTORY_PINNED_TTS`); a failed synthesis fails the item, no fallback engine.
- `pipeline/audio_rebuild.py`: candidate = record without `tts_chunked` (the only multi-sentence marker); regenerated through the pinned stage; Laravel replace happens before the local `audio_rebuilt_at` stamp.
- Delivery: kinds `agent_history.article` and `agent_history.article_audio` of the shared Laravel delivery outbox (`pipeline/delivery.py`); local generation never depends on Laravel availability. The local record id derives from the operation item and is sent as `idempotency_key` (`laravel_stage.py`).

## 10. Laravel article submit (idempotent)

`POST /api/app_qy_v1/ai_tools/article/worker/submit` — `AppQyV1WorkerArticleSubmitRequest` (`idempotency_key` nullable, ≤ 128) → `AppQyV1ArticleController::workerSubmit` → `AppQyV1AgentHistoryArticleSubmissionService::submit` (single orchestration path; controller owns no persistence).

- Article identity is content-addressed: `article_` + first 40 hex of `sha256("0:<title_md5>:<content_md5>")`. An existing article is found by `source_record_id` (the idempotency key, `findAgentHistoryBySourceRecordId`) or by canonical content hashes; when both exist and differ, the source article is aliased to the canonical one (`aliasArticleToCanonical`). Only `sha256(idempotency_key)` is stored with the raw key as `source_record_id`; `submission_fingerprint` = sha256 of the text/language/titles/reference fields.
- Every step runs on first delivery and on retry (never an early "exists" return): `insertOrIgnore` on the unique `article_id`; `replaceAgentHistorySubmission` converges row + metadata; a non-managed-daily article with that id → 409 (`article.worker_identity_conflict`).
- Audio: deterministic `daily/<language>/<article_id>.mp3`, `metadata.audio_sha256`; timestamps change only when bytes change; `tts_chunked` persisted.
- Words: `AppQyV1ArticleWordModel::createFromArticleWords` upsert on `article_id + word_md5`.
- Document: `AppQyV1DailyReadingDocumentService::createForWorkerArticle` `insertOrIgnore` on unique `source_type + source_key` (`article`, `<article_id>`).
- Publication: `AppQyV1TranslationEventModel::emitOnce` with dedup key `<article_id>:<submission_fingerprint>` inside `AppQyV1ArticleModel::mutateMetadataByArticleId` (transaction, deadlock retries, `lockForUpdate`); `publication_event_fingerprint` marker set in the same transaction, so a changed submission publishes once more and an identical retry never does.
- Schema: migration `AppQyV1_2026_08_20_220900_add_submission_idempotency_keys.php` (uploaded_documents `source_type, source_key` unique; translation_events `deduplication_key` unique with `event`), applied by `php artisan sys:init`.
- Constraints: keep orchestration out of the controller; keep DB unique keys as the concurrency guards (not JSON metadata); keep marker + keyed outbox insert in one locked transaction; keep `tts_chunked` the single multi-sentence marker; keep audio replacement deterministic.
