# FIX 20260727_2343 — Analysis & Fix List

Source problems: `docs_fix/origin/b.txt`. Ends (from root README): backend `poly_apps/laravel_main`, pycore `./pycore`, UI `poly_apps/pycore_laravel_wordflow_ui` (`/pycore-manager`, `/wordnew`), chrome extension `apps/mcp-chrome`, ncore `./main.js` + `./apps/`.

This batch: analysis first, then the fixes are executed in the same session and the aligned final code is appended at the bottom of this document.

## Issue list (from b.txt)

1. **qwen3tts / RPC v2**: `RPC timeout after 30000ms: local.tts.test` — engine cold start (isolated venv + model load) takes minutes, longer than the client deadline.
2. **`database is locked`** in pycore `RequestProcessor`.
3. **Pycore UI Laravel endpoint switch** not persisted to user data / not restored on next start.
4. **agent-history → laravel → wordnew Quantum Dossiers chain broken**: (1) `GET /api/app_qy_v1/media/books/article_...` 404; (2) audio `/static/app_qy_v1/audio/agent_history/en/{id}.mp3` 404 (upload alignment); (3) "Play from this article" / "Open read-along reader" broken.
5. **Cover pipelines misaligned**: book covers should come from mcp-chrome Google image search (task enabled), vocabulary library covers from Gemini image generation; the two ends disagree.
6. **wordnew `#/shelf` Default Vocabulary Group progress** (target/read/memorized) not synced with backend and not loaded on start.

## Issue 1 — local.tts.test RPC timeout

### Root cause (confirmed)
Client-side deadline is a fixed 30s; the server side is already correct.

- `poly_apps/pycore_laravel_wordflow_ui/core/api-libs/pycore/PycoreWs.ts:158` — `DEFAULT_RPC_TIMEOUT_MS = 30_000`; deadline frozen at enqueue (`nativeCall`, lines 273-303), `armPendingTimer` rejects `RPC timeout after ${timeoutMs}ms: ${method}` (lines 189-206).
- `core/api-libs/pycore/PycoreApiSpeech.ts:61-66` — `testTts` calls `callRpc(local.tts.test, params)` **without** `timeoutMs` (same for `testStt`/`testOcr`/`testAiChat`, lines 70-99). `callRpc` already accepts `timeoutMs` (`PycoreWs.ts:635`).
- RPC v2 ID callback: already correct — responses matched by `request_id || event_id || id` (`PycoreWs.ts:225-242`), durable `rpc_completion` events for late completions (`:552-571`); server async path `pycore/pyutils/rpc_v2/server/websocket_handler.py:_handle_request` (253-466) with ACK/replay.
- Threading: already correct — `pycore/callmodule/rpc_routes/local_engine_test_routes.py:260` runs `_tts_test` on a THREAD_BUS worker via `await_bus_task(..., timeout=None)` (`pycore/pyfoundations/serialized_worker.py:167-198`).
- Readiness wait exists server-side but inside the call: `tts_service_manager.py:553` → `managed_services.ensure_running()` → `_wait_healthy(spec, 180s)` (`pycore/pyutils/common/managed_service.py:81`); qwen3tts `_wait_healthy` polls `/health` up to 180s (`pycore/pyutils/tts/qwen3tts_service.py:218-231`). Cold start legitimately exceeds 30s.

### Fix (UI only, no pycore change)
`PycoreApiSpeech.ts`: add `ENGINE_TEST_TIMEOUT_MS = 10 * 60_000` and pass it to `callRpc` in `testTts`/`testStt`/`testOcr`/`testAiChat`.

## Issue 2 — database is locked (RequestProcessor)

### Root cause (confirmed)
- Log site: `pycore/pyutils/rpc_v2/server/request_processor.py:70` — some route handler raised `sqlite3.OperationalError: database is locked`.
- DB: SQLite `pycore_state.sqlite3`, `pycore/database/repositories/state_repository.py:36-55`. Per-thread connections, `isolation_level=None`, manual `BEGIN IMMEDIATE` (`:62`), WAL on. **No `busy_timeout` PRAGMA anywhere in pycore; `sqlite3.connect` default timeout 5s; zero retry.**
- Six `StateRepository()` instances share the file (websocket_handler, rpc_delivery_service, operation_service, operation_event_service, laravel_log_mirror_service, sse_broadcaster); read-only methods also use `BEGIN IMMEDIATE`, so all traffic competes for the single writer slot.

### Fix (pycore only)
`state_repository.py::_get_conn` (lines 45-55): `timeout=30.0` + `PRAGMA busy_timeout=30000` per connection.

## Issue 3 — Laravel endpoint switch persistence

### Root cause (confirmed)
The pycore-manager top-bar switcher IS wired (`PcLaravelEndpointSwitcher.tsx:159` → `PcLaravelEndpointContext.tsx:141` → `PycoreLaravelApi.ts:77` `laravel_api.select` → `pycore/callmodule/rpc_routes/laravel_api_routes.py:103` → `LaravelEndpointManager.select()` `laravel_endpoint_manager.py:566` → `_save` at `:583` → `user_data.json` section `laravel_api`; restore via `_load` `:223` + stored-first `resolve()` `:323-395`). Two genuine gaps:

- **Gap A (pycore)**: `resolve()` sweep winner is persisted over the user's stored choice — `laravel_endpoint_manager.py:381-385` calls `self._save(endpoints, winner)`. If the stored endpoint is briefly down at startup, the user's pick is silently overwritten and "not restored" next start. Fix: in `resolve()` only cache in-process (`self._resolved = winner`), never `_save`; only `select()` writes `current`.
- **Gap B (UI)**: the wordflow/global header switcher `components/ApiEndpointSwitcher.tsx:131` → `services/ApiManager.ts:443-469` persists only to localStorage (`api_user_modified`/`api_current_endpoint`, lines 51-53), never notifies pycore. Fix: after successful `switchEndpoint`, fire-and-forget `pycoreLaravelApi.select(fullUrl)`.

## Issue 5 — cover pipelines misaligned

### Root cause (confirmed)
- Book covers: UI trigger (`WfNewHomeContent.tsx:213-223` → `prioritizePosters` → `/assist/poster/priority`) → mcp-chrome `media_image` worker claims `['cover','poster']` (`media-image-worker-service.ts:105-128`), Google→Bing search, POST `/assist/submit`. URLs/fields match, BUT: mcp-chrome sends `sourceId: image.sourceUrl.slice(0, 512)` (`media-image-worker-service.ts:203,225`) while Laravel validates `'source_id' => 'nullable|string|max:64'` (`AppQyV1AssistController.php:139`) → 422 → infinite outbox retry → **book cover pipeline stalled**.
- Vocabulary library covers: Laravel claim payload is a Gemini-style generation prompt (`AppQyV1CoverPromptBuilder`, `AppQyV1AssistMediaOperations.php:66-85`, includes `size: '1024x1024'`), but mcp-chrome `cover` branch discards it and does Google search (`media-image-worker-service.ts:136-146`, `media-image-search.ts:30-35`). Gemini generators exist but unwired (`GeminiClient::generateImage` `app/Services/GeminiClient.php:247`; pycore `gemini_client.py:179`; mcp-chrome `gemini-image-worker-service.ts` drives word images only).
- Library trigger never fires from UI: library endpoint always returns non-null `image_url` (`AppQyV1VocabularyLibraryPublicController.php:979-981` + `AppQyV1VocabularyCoverService.php:73,99-106`), so `!group.imageUrl` check (`WfNewHomeContent.tsx:208-211`) never triggers; `libraryRowToContentGroup` (`WfNewApiMappers.ts:323-335`) drops `cover_status`.

### Fixes
1. `AppQyV1AssistController.php:139` — `source_id` max:64 → max:512 (verify `poster_source_id` column ≥512 or truncate server-side).
2. `AppQyV1VocabularyLibraryPublicController.php:979-981` — return `image_url => null` unless cover status is `ready` (keep deterministic URL in separate field), aligning with book behavior.
3. `apps/mcp-chrome/.../media-image-worker-service.ts` cover branch — prefer Gemini generation from `payload.prompt` (extract shared `generateViaGemini(prompt)` from `gemini-image-worker-service.ts` start→poll logic), Google search as fallback; submit with provider `'gemini'`.
